# A 类 · 功能、套餐与版本事实

版本：v0.1（阶段 1）· 2026-10-24

> 状态：A-01 已选定 **Amazon Q Developer Free Tier**；真实材料与人工参考草稿已建立，**待乙确认**；系统未运行、丙未复核。B/C 未开始。

## 1. 问题模板

> `[产品] 免费版的额度是多少？按月重置、按次消耗，还是一次性额度？`

回答意图默认是**客观搜查**：直接回答额度数值和计量方式，附产品、版本、套餐、地区、时间和出处。用户没有要求建议时，不输出购买建议或推荐档位。

## 2. 必须回答的原子问题

| ID | 原子问题 | 不能省略的原因 |
|---|---|---|
| A-Q1 | 免费版是否存在？官方名称、适用地区、账号类型是什么？ | 先确认查的是哪个套餐 |
| A-Q2 | 额度数值是多少？单位是什么（次、token、积分、字符、请求等）？ | “有额度”不等于回答额度 |
| A-Q3 | 额度如何重置或消耗：按月重置、按次消耗、一次性，还是其他规则？ | 用户问题直接问计量方式 |
| A-Q4 | 适用于哪个版本、套餐、地区、账号类型或计费周期？ | 防止把 Pro／其他地区套到 Free |
| A-Q5 | 官方口径的发布时间、最后更新时间或生效时间是什么？ | 防止过期页面当当前事实 |
| A-Q6 | 官方定价页、帮助中心、文档、更新记录之间是否不一致？ | 官方材料也可能互相矛盾 |

每个问题都要在 `reference.md` 有明确状态；不能只回答 A-Q2 而跳过 A-Q3。

## 3. 证据结构

A 类至少应覆盖：

| 证据类型 | 作用 | 注意 |
|---|---|---|
| 官方定价页 | 套餐名、价格、额度、计费周期 | 记录地区、币种、页面更新时间 |
| 官方帮助中心／文档 | 额度如何重置／消耗、限制条件 | 与定价页交叉核对；冲突要保留 |
| 官方更新记录／公告 | 额度变更、生效时间 | 旧额度和新额度分开，不合并 |
| 独立来源（如有） | 实际使用报告、第三方说明 | 只能证明“该来源这样说”；同源不计独立 |

硬要求：

- 至少一条官方 `READ` 证据；额度数值和重置／消耗方式都要有出处。
- 每条 `READ` 证据必须有原句、定位、SHA-256、获取时间；没有这些就不能标 `READ`。
- 官方页面写“up to”“最多”“每月赠送”等限定，必须保留；不能改写成固定额度。
- 官方额度与“实际可用量”分开；没有实测就不声称“一定能用满”。
- 官方 benchmark、营销页、销售话术不是独立实测。

## 4. 类型门槛

A 类案例可以进入评估，必须同时满足：

1. 产品身份、版本／套餐、地区明确；未知的在 `scope` 和缺口中说明。
2. A-Q1 至 A-Q6 都有答案或明确缺口。
3. 额度数值与重置／消耗方式分别有依据。
4. 官方页面之间的不一致（如有）已保留。
5. 没有把其他套餐／地区／版本的额度套用到目标对象。
6. 参考判断由乙确认；系统运行与独立复核按通用流程完成。

## 5. 常见阻断错误

- 只写“免费版有额度”，不写数值和单位。
- 把“按月重置”写成“一次性”，或把“按次消耗”写成“按月”。
- 用 Pro／Team 页面证明 Free。
- 用美国区页面证明中国区权益。
- 用旧版本文档证明当前版本，且不标时间。
- 把“最多 100 次”写成“固定 100 次”。
- 把官方营销页的“无限”当成无限制事实。
- 把搜索摘要当官方原句。
- 把第三方转述当独立来源。
- 没有官方依据，却用社区帖子断言额度。

## 6. 选题检查

选题时先回答这些问题；任一为“否”就不要把该题计入正式 A 案：

- [ ] 产品有可公开访问的官方定价／帮助／文档页面？
- [ ] 免费版有明确名称，且能确认地区？
- [ ] 额度数值和重置／消耗方式至少有一处官方说明？
- [ ] 能区分版本、套餐、地区，不会混淆？
- [ ] 页面有可记录的更新时间或至少能记录获取时间？
- [ ] 如果官方页面冲突，能保留双方而不是强行选一个？
- [ ] 用户问题原话已经拿到，不是自己编的模板？
