- `开始这里` 已说明：原画像及修补指令是历史依据，当前任务以派单和最新规范为准。

当前仓库事实：

- 本阶段之前没有 `cases/` 目录；当前 A-01、B-01、C-01 均有真实材料与人工参考草稿。

### 2.1 六项之外的补充字段

以下字段是本项目为“阶段 1 规范与评估”新增，**不替代六项**：

这些字段如果需要进入运行时快照，必须走 `src/contracts` 和三人对齐；当前只在 D1 Markdown 记录中使用。

## 6. 不得宣称

在下列条件满足前，不得对外或对队友宣称：

| 不得宣称 | 需要先满足 |
|---|---|
| “D1 三案已完成” | 三个真实案例目录、六项材料、参考确认、系统对照、丙复核 |
| “A-01 已人工确认／人工金标准” | 乙逐条确认 `reference.md`；丙完成独立复核；系统对照即使缺失也要明确标注 |
| “B-01 已人工确认／开发者共识” | 乙逐条确认 `reference.md`；丙独立复核；明确只有 2 位 HN 直接作者 + 1 个 20 任务测试，不是群体共识 |
| “C-01 已证明 50 是多个独立来源” | 乙确认 `reference.md`；丙复核；独立来源计数必须按源头，C-01 当前为 0 |
| “评估器测试通过 = D1 通过” | 工具测试只证明确定性规则；D1 还需要真实运行、参考确认和丙独立复核 |
| “六项材料已满足” | 每案逐项填写并有真实证据；本文件只证明要求已被定位和落实为模板 |
| “已独立复核” | `review.md` 有丙的签署、时间、独立判断和依据 |
| “系统已运行”或“已有快照” | 真实 `investigation_id`；成功时有 `snapshot_id` 和版本；失败时保留错误 |
| “真实冲突已找到” | B-01 草稿有双方原句、条件、关系（X1/X2）；仍需乙确认和丙复核；不能把它写成开发者共识或 2026 产品定论 |
| “案例已通过评估” | 评估对象无阻断错误，G1–G12 逐项记录；系统失败时只能写“无法评估”或“系统失败” |
