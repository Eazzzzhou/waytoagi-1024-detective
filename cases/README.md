## 3. 状态模型

状态分三个维度，不用一个“完成”字段掩盖缺口。

| 维度 | 允许值 | 进入条件 |
|---|---|---|
| 材料 | 未开始 | 没有真实材料，只有模板或选题计划 |
| 材料 | 待人工核实 | 已有真实来源、证据和草稿判断；尚未由乙逐条确认 |
| 材料 | 人工已确认 | 乙已在 `reference.md` 签署确认；仍不等于已独立复核 |
| 系统 | 未运行 | 没有提交过该系统问题 |
| 系统 | 已提交未完成 | 已取得调查 ID，但尚未到终态；不得写结果 |
| 系统 | 系统已运行（失败） | 已到终态且失败；保留真实错误，不得改写成“没有结果” |
| 系统 | 系统已运行（成功） | 已取得已发布快照；记录快照 ID、版本和生成时间 |
| 复核 | 未复核 | 没有丙的独立复核记录 |
| 复核 | 已独立复核 | 丙已在 `review.md` 记录独立判读、对照意见和依据 |

最终评估结论只在材料、系统、复核三项都达到对应条件后填写：`通过`、`有条件通过`、`不通过`、`无法评估`。系统失败不等于案例材料无效；它只表示系统对照无法完成或该系统结果失败。

## 4. 工作流程

1. **选题。** 从核心提供的候选产品或用户真实问题中选题；仓库当前没有候选清单和 T0，不得自己编造产品名单或把试查自动计入正式三案。
2. **建工作位。** 在 `cases/<A|B|C>/<案例 ID>/` 下建立目录，复制 `_template/case.md`、`reference.md`、`review.md`。
3. **固化问题。** 原样记录用户问题，不改写、不补全；确定回答意图、产品身份、版本、套餐、地区和核查范围。
4. **独立研究。** 按 [D1-案例规范](D1-案例规范.md) 记录检索、原文、译文、定位、获取状态、hash、来源类型和独立性。搜索摘要不能升级为原句。
5. **形成材料判断。** 建立原子问题、主张、证据关系、冲突和缺口；自动化可整理候选，但“原句是否支持结论”“是否同源”“缺口属于哪类”必须由人确认。
6. **人工参考判断。** 在 `reference.md` 写逐问结论、主张状态、不确定性、可能改变判断的新证据；由乙确认后才能标“人工已确认”。
7. **系统运行。** 只用原问题和必要的真实身份确认依据提交；不得把 `reference.md`、评估标准、预期主张或复核意见送入系统。记录调查 ID、状态、错误、快照 ID 和版本。
8. **对照与评估。** 先按材料核对参考判断，再按快照核对系统结果；逐原子问题和逐引用记录一致、部分一致、冲突、缺失或不可比。按 [D1-评估标准](D1-评估标准.md) 检查阻断性错误。
9. **独立复核。** 丙先只看问题与原始材料，形成独立判断，再读参考判断和系统结果；在 `review.md` 记录同意、分歧、依据和未解决项。
10. **更新索引。** 只按实际状态更新上表；没有发生的运行、快照或复核不得预填。

## 5. 参考隔离

- `reference.md` 只供人工评估和复核使用，**不得作为系统运行时的输入**。
- 系统运行时只接收：用户问题原文、用户真实提供的身份确认依据（如有）。不得接收：参考结论、预期主张、证据清单、评估标准、复核意见、本目录中的任何文件内容。
- `src/` 和 Worker 不导入、不读取 `cases/`。未来如做离线对照工具，只能在快照发布后读取快照与参考文件，不能把参考内容回灌到调查、检索或生成。
- 不得把参考结论改写成问题、身份依据、检索词或提示词。运行前记录 `system_inputs.reference_used: false`；复核时检查。
- 问题原文需计算 SHA-256 并记录，确保系统提交的问题与案例问题一致。

## 6. 完成定义

| 层级 | 必须满足 |
|---|---|
| 材料可用 | 六项材料齐全；参考判断通过适用标准（G1–G12 中适用项）；无阻断性错误；乙已确认 |
| 系统对照完成 | 有真实调查 ID 和终态；成功时有快照 ID／版本；逐问对照已记录；失败也如实记录 |
| D1 交接完成 | 三案材料可用；至少一案有海外原句与真实冲突（否则明确报告未完成）；丙已独立复核 |
| 最终通过 | 被评估对象无阻断性错误，且适用标准全部通过；`有条件通过` 必须列出未关闭条件和影响 |

## 7. 新增案例

PowerShell 示例（把 `<TYPE>`、`<ID>` 换成实际值）：

```powershell
New-Item -ItemType Directory cases/<TYPE>/<ID>
Copy-Item cases/_template/case.md cases/<TYPE>/<ID>/case.md
Copy-Item cases/_template/reference.md cases/<TYPE>/<ID>/reference.md
Copy-Item cases/_template/review.md cases/<TYPE>/<ID>/review.md
```

命名规则：类型前缀 `A`／`B`／`C` 加两位序号，`A-01` 起；同一 ID 不复用。需要替换案例时建立新 ID，并在旧目录标注“已被替代”，不覆盖历史证据。
