## 4. 系统对照能力

| 文件 | 作用 |
|---|---|
| `scripts/d1/rules.ts` | 确定性规则、运行记录 Zod Schema、来源分组、COMPLETED/NOT_RUN 构建 |
| `scripts/d1/case.ts` | 案例问题/reference 读取、front matter hash 校验 |
| `scripts/d1/store.ts` | `cases/runs/<caseId>/<runId>.json` 只追加；`wx` 不覆盖 |
| `scripts/d1/evaluate.ts` | CLI：只读 repository/answer/advice；真实运行或 NOT_RUN |
| `tests/unit/d1-evaluation.test.ts` | 11 项规则测试 |
| `tests/integration/d1-evaluation.test.ts` | 1 项真实 PostgreSQL 只读读取/无写入测试 |

运行记录保存：案例 ID、调查 ID、快照 ID、运行时间、app/Node/contract 版本、人工参考路径与 hash、快照/回答副本、逐项 checks、独立来源分组、issues、review 状态、verdict。评估器只读，不写 investigation/snapshot/answer/advice；不覆盖历史快照或旧运行记录。

### 4.1 规则

| ID | 规则 |
|---|---|
| R1 | 调查/快照/回答符合共享 Zod 契约 |
| R2 | 引用证据/主张 ID 存在 |
| R3 | 引用原句与保存证据逐字符匹配 |
| R4 | 必要来源元数据不缺失 |
| R5 | 同一 sourceUrl/upstream/originGroup 不重复标独立；译文不作第二独立来源 |
| R6 | 客观问题快照无未请求的 Advice |
| R7 | 失败/非成功任务不当有效结果 |
| R8 | 历史快照版本/父链成立；评估器只读 |
| R9 | 案例 ID 与 investigation/snapshot 关联 |
| R10 | 空回答或无引用告警 |

不自动判定：引用是否真正支持主张、来源是否独立、是否过度推断、观点是否代表群体、展示是否清楚。

## 10. 接入后的运行方式

```powershell
# 三案分别运行；每次使用新的 run-id，旧记录不会被覆盖
npm run d1:evaluate -- --case A-01 --investigation <UUID> --snapshot <UUID> --run-id <唯一ID>
npm run d1:evaluate -- --case B-01 --investigation <UUID> --snapshot <UUID> --run-id <唯一ID>
npm run d1:evaluate -- --case C-01 --investigation <UUID> --snapshot <UUID> --run-id <唯一ID>
```

评估器会读取该 snapshot 的 answers 和 advice count，只读；不创建/更新/删除调查、快照、回答或建议。
