# D1 案例规范

本文件规定材料结构与过程，评估结论见[评估标准](D1-评估标准.md)，当前问题只见[案例状态](D1-状态与验收记录.md)。运行时字段直接用 src/contracts；案例的 Q/E/C 编号、地区和研究时间等记录不能私自加入 strict 快照。

## 类型与最低材料

| 类型 | 必须回答 | 类型门槛 |
|---|---|---|
| A 功能／套餐／额度 | 产品、免费层性质、数值与单位、消耗条件、月度／重置、账号地区、版本时间、官方页面差异 | 至少一条官方 READ；额度与周期分别判断，未知边界保留 |
| B 海外报告／冲突 | 官方原话与条件、海外使用者实际报告、支持／反驳／条件不同、时间版本可比性及局限 | 官方宣称 READ + 海外原文 READ；真实冲突保留双方，未找到就明确该项未完成 |
| C 来源关系 | 至少三条说法的原文、出处、传播／翻译／改写、上游、独立性及仍缺的证据 | 至少三条说法／来源；评估同源关系，没有发现也如实记录，不为凑数判独立 |

每案六项必备：①案例ID、产品版本／套餐；②问题原话和客观／建议意图；③URL、原句、站点、公开作者、发布时间、获取日期及读取状态；④证据与主张关系、同源依据；⑤冲突和有范围的缺口；⑥实际核查者、时间及独立复核记录。未知明确标注，不留占位符冒充内容。

## 文件分离

| 文件 | 唯一内容 |
|---|---|
| case.md | 问题、身份、范围／时间、检索与证据、主张关系、冲突缺口、实际系统输入与运行 |
| reference.md | 逐问参考判断、关键依据、局限、实际人工确认、系统逐问对照及评估 |
| review.md | 实际复核者的独立判断、阅读顺序、与参考／系统的分歧、阻断检查和签署 |

参考及预期证据不进入系统运行。复核者先只看问题和原始材料；case.md 的主张／判断也属于结论，不应提前展示给独立判读者。再读参考、最后看系统结果。已接触结论者只能如实记录非盲复查，不填 blind=true。

## 材料记录

- 问题逐字保存，仅提交时按 API 去首尾空白；记录 UTF-8 SHA-256。拆 Q-ID → C-ID → E-ID，背景单独标明。案例本地编号不冒充系统 UUID。
- 确认产品需官网和可定位依据；版本／套餐／地区／账号及语言范围写清，未知不猜。Free 不是版本，抓取日期不是版本或生效日。
- 研究起止、事实基准日、适用期、来源发布、实际获取、系统运行、复核时间分开，使用含时区时间；新获取另记，不覆盖旧获取时间。
- READ 必须有实际原句（≤300字符）、具体定位、原始内容SHA-256，且无读取错误；保存依据须能复核。hash不是网页归档，单有hash不能还原全文。
- NOT_FETCHED / SNIPPET_ONLY / FAILED / RESTRICTED 不填原句、译文、定位或hash；失败／限制记真实原因，未知写UNKNOWN；摘要只作线索。
- 原句保持原有字符，译文独列；定位到段落、评论、页码、时间点，并保留必要条件。关键引用不是译文、改写或无法复找的拼接句。
- 元数据记录来源／内容性质、作者、发布时间、获取时间、版本套餐；实际未知为null。官方来源不自动等于事实或独立实测。
- 同源记录 upstreamUrl、independence、originGroupId、reason；SHARED_ORIGIN有分组，非UNKNOWN有理由。按具体主张及支持／反驳关系核对源头，不能直接数分组ID；UNKNOWN不计独立支持。
- 主张带 kind、verificationStatus、reason、scope；只有READ可SUPPORTS／REFUTES，其他关系为CONTEXT／IRRELEVANT／UNCERTAIN。官方宣称被支持只证明宣称存在。
- 冲突关联主张和至少两条不同证据，保留双方条件、解释及未解决点。未发现冲突不伪造X记录，应写检索范围／缺口。
- 缺口用 NOT_FETCHED / READ_FAILED / NOT_FOUND_IN_SCOPE / IDENTITY_UNCLEAR / INSUFFICIENT_EVIDENCE；未找到必须有searchScope。关联具体主张，整体缺口明确写整体。读取受限是readStatus=RESTRICTED，不能新增同名Gap枚举。
- 实际确认者逐条核对原句、范围和关系后署名；说明模型协助了什么、人工核对了什么。原文优先于参考，参考错就修参考。

## 正式运行与对照

系统只接收固定问题原文和必要真实身份依据，不接收case/reference的预期主张、证据清单、检索词或评估标准。保存问题hash和reference_used=false，通过正式API／Worker执行，不直接插库造成功。

记录 investigationId、提交时间、终态／stage、真实error；成功还记snapshotId、version、generatedAt、contractVersion、身份、检索及回答。失败无快照也保留ID／错误；未运行才记NOT_RUN。历史结果标版本时间。

逐 Q/C/E 对照：一致／部分一致／冲突／系统缺失／不可比／系统错误，并核对引用结构与语义。不能只按文字相似判断，也不能以参考预设系统正确性。评估工具的能力与限制见[runs约定](runs/README.md)。

## 完成门槛

材料可用：六项完整、实际人工确认、适用G项通过、无X阻断项。系统对照完成：正式真实成功结果可核对、逐问对照完成；失败如实记录但不算成功对照。D1最终通过：三案满足材料要求、至少一案海外原句与真实冲突、真实对照和实际独立复核完成、无阻断项。

共同内容与隐私／引用要求遵循[协作边界](../docs/甲与乙丙协作边界.md#核查与展示的共同要求)。缺口允许保留；未完成的门槛明确未完成，不降格为通过。
