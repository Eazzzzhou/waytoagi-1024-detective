# C 类 · 来源关系、转载与证据不足

版本：v0.1（阶段 1）· 2026-10-24

> 状态：C-01 已选定 **GitHub Copilot Free 的“2,000 completions + 50 chat requests”说法**；真实来源、翻译、引用链、人工参考草稿已建立，**待乙确认**；系统未运行、丙未复核。

## 1. 问题模板

> `关于 [产品] 支持 [功能] 的几条说法，哪些是独立来源，哪些只是同一作者或同一文章的转载？`

回答意图默认是**客观搜查**：逐条列出说法、源头、传播关系、独立来源数量和证据缺口。不是判断功能真假本身，而是判断“这些说法之间是否真的互相独立”。

## 2. 必须回答的原子问题

| ID | 原子问题 | 不能省略的原因 |
|---|---|---|
| C-Q1 | 待核查的说法逐条原文是什么？最早出处是谁？ | 先固定比较对象 |
| C-Q2 | 每条说法的直达 URL、作者／账号、发布时间、定位是什么？ | 没有定位无法判断同源 |
| C-Q3 | 哪些是同一作者、同一文章、同一 upstream、同一实验或同一新闻稿？ | 核心是来源关系 |
| C-Q4 | 哪些可以判为独立？依据是什么？ | 独立性要有理由 |
| C-Q5 | 是否存在一手来源？转载是否改变原意、删减条件或增加结论？ | 转载可能失真 |
| C-Q6 | 现有证据能支持什么，证据不足的部分缺什么？ | 允许结论是“证据不足” |

至少三条说法／来源；少于三条不足以展示“几条说法”的关系。至少评估一组同源关系，或明确报告未发现同源。

## 3. 证据结构

C 类至少应覆盖：

| 证据类型 | 作用 | 注意 |
|---|---|---|
| 最早出处／一手来源 | 确定源头 | 官方发布、原作者帖子、原始 issue、原始视频等 |
| 转载／改写／跨平台发帖 | 判断传播关系 | 同作者、同文章、同 upstream；跨平台不自动独立 |
| 二手报道／聚合页 | 展示传播链 | 不能替代一手来源；引用要回到原文 |
| 官方文档（如相关） | 功能事实基线 | 只证明官方这样说，不证明所有说法独立 |

硬要求：

- 每条说法有直达 URL、作者、时间、定位；`READ` 证据有原句、定位、hash。
- 同源判断要写依据：同一作者、同一文章标题／段落、同一 upstream URL、同一实验数据、同一新闻稿。
- `SHARED_ORIGIN` 必须有 `originGroupId`；`UNKNOWN` 不计入独立来源。
- 独立来源数按源头计，不按 URL 数或平台数计。
- 转载改变原意、删条件、加结论时，要保留原文与转载文对比，不能只写“转载”。
- 证据不足时写 `INSUFFICIENT_EVIDENCE` 或明确缺口，不强行判断真假。

## 4. 类型门槛

C 类案例可以进入评估，必须同时满足：

1. 至少三条可定位的说法／来源。
2. 每条说法有原文或明确的读取状态；失败保留 URL 和原因。
3. 至少一组同源关系已评估，或明确报告未发现同源。
4. 一手来源已尝试定位；找不到时写缺口。
5. 独立来源数量按源头计算，理由可解释。
6. 没有把跨平台、转载、同作者跨发当成独立证实。
7. 参考判断由乙确认；系统运行与独立复核按通用流程完成。

## 5. 常见阻断错误

- 把同一作者在 X、HN、博客的三次发帖算成三个独立来源。
- 把四个站点转载同一篇文章写成“四家媒体证实”。
- 把同一新闻稿的多个改写版本当成独立报道。
- 把多个帖子引用同一个 GitHub issue 当成多方独立报告。
- 跨平台自动判独立，不看作者和 upstream。
- 无法确认同源却判 `INDEPENDENT`。
- 只用聚合页／搜索摘要，不回到一手来源。
- 转载删掉条件，结论被扩大，却没有对比原文。
- 把“独立来源数为 0／1”写成“多方证实”。
- 把证据不足写成功能不存在。

## 6. 选题检查

选题时先回答这些问题；任一关键项为“否”就不要把该题计入正式 C 案：

- [ ] 产品有一个具体功能，且公开讨论中出现多条说法？
- [ ] 至少三条说法有可访问的直达 URL？
- [ ] 能取得作者、时间、定位，而不只是搜索结果？
- [ ] 至少有一条潜在的转载／同作者／同 upstream 线索？
- [ ] 能找到或尝试定位一手来源？
- [ ] 能区分“同一文章转载”和“不同作者独立测试”？
- [ ] 如果所有来源都同源，能如实写独立来源数为 0／1？
- [ ] 用户问题原话已经拿到，不是自己编的模板？
