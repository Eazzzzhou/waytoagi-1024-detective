摘要：AI 能快速给出答案和链接，但搜索结果不等于证据。本文基于 SIFT 四步法，用 GitHub Copilot Free 的真实资料演示如何调查来源、追溯原文、识别过期信息，并整理出可直接复用的检索模板。

关键词：AI搜索、SIFT四步法、信息检索、事实核查、GitHub Copilot、人工智能、新手教程

有些 AI 回答并不是假的，麻烦在于它曾经是真的。

比如你问：

GitHub Copilot Free 每个月是不是有 2,000 次代码补全和 50 条聊天消息？

你很容易搜到一份 GitHub 官方公告。标题、日期、数字都对，来源也足够正式。到这里，很多人会觉得已经查完了。

但这份公告发布于 2024 年 12 月。到了 2026 年，GitHub 当前套餐文档仍写着 Copilot Free 每月最多 2,000 次补全，套餐页对 AI 用量和模型使用则已经采用 GitHub AI Credits、自动模型选择等表述。旧公告能证明“发布时怎样”，却不足以单独证明“现在仍然怎样”。

这就是 AI 搜索里最容易漏掉的一层：找到一个支持答案的链接，不等于找到了适合当前问题的证据。

上一篇文章解决的是“AI 已经给出一段答案，怎样快速检查其中的数字、日期和范围”。这一篇再往前走一步：从一条二手说法出发，怎样离开当前页面，调查来源，并追到更适合回答问题的原始材料。

这套方法不是我临时编出来的。核心来自 Mike Caulfield 提出的 SIFT 四步法，同时参考了 Civic Online Reasoning 的横向阅读方法和 ACRL 信息素养框架。为了适应 AI 检索，我只额外增加两项操作：先拆分待核验主张，最后保留证据记录。

一、为什么“让 AI 再搜一次”通常解决不了问题

当一条回答让人不放心，最直接的反应往往是：

再问一次同一个 AI；

换一个模型重新回答；

让它多给几个链接；

打开排名最靠前的搜索结果。

这些动作可能带来更多内容，却未必带来新的证据。

两款模型可能引用同一篇旧公告；十篇文章可能都转载自同一份新闻稿；搜索摘要里的一句话，也可能省略了正文里的时间和限制条件。

还有一种更隐蔽的情况：来源本身没有问题，只是不适合回答你现在的问题。

发布公告适合回答“当时推出了什么”；当前帮助文档更适合回答“现在能用什么”；价格页适合核对套餐，但不一定能证明产品效果；企业自己的案例可以说明它如何描述自己，却不能单独证明它优于所有竞品。

所以检索真正要解决的不是“有没有链接”，而是三个问题：

谁发布了这条信息？

这个来源具体支持哪一句话？

它是否适合回答当前时间、范围和用途下的问题？

二、SIFT 四步法到底是什么

SIFT 不是一个 AI 提示词，也不是“看网站是否专业”的评分表。

Mike Caulfield 在公开说明中把它概括为四个动作：

SIFT 动作要解决的问题实际动作Stop，先停一下我现在究竟要确认什么？暂停阅读和转发，明确任务与风险Investigate the source，调查来源这是谁发布的，专业性和利益关系是什么？离开当前页面，查看外部资料如何评价这个来源Find better coverage，寻找更好的报道或材料有没有更适合回答当前问题的来源？找当前文档、权威资料和不同证据链Trace to the original context，追溯原始语境这句话、数字或图片原本出现在什么上下文里？回到公告、论文、数据表或完整记录

SIFT 的重点不是在一张陌生网页里读得更久，而是适时离开它。

Civic Online Reasoning 将这种做法称为“横向阅读”：遇到不熟悉的来源时，打开新的页面，看看可信来源如何描述它，而不是只在原网站内部寻找“关于我们”和自我介绍。

ACRL 的信息素养框架也提醒了两个容易被忽略的事实：

权威性与使用场景有关，同一份材料不适合证明所有结论；

检索通常是非线性、反复调整的过程，第一轮搜索没有得到合适结果很正常。

三、开始搜索前，先把问题改成“证据任务”

“帮我查一下 Copilot Free 能不能用”太宽了。

AI 会把功能、价格、地区和主观建议混在一起，最后给你一个看起来完整、实际上很难核验的答案。

更有效的做法，是先写一张很短的检索任务卡：

字段本文案例待核验主张Copilot Free 当前每月提供 2,000 次代码补全和 50 条聊天消息核对截止日期2026 年 8 月 31 日适用对象个人开发者的 Copilot Free 套餐优先来源GitHub 当前套餐文档、帮助文档、正式公告可接受结论当前成立 / 历史上成立 / 部分成立 / 暂无法确认

这里最重要的是“截止日期”。

如果没有这个字段，AI 找到 2024 年的官方公告，也可以理直气壮地说自己给了官方来源。但我们要问的是当前套餐，证据自然要优先选择当前维护的文档。

可以把任务直接写成下面这样：

请核验下面的主张，不要先回答“是”或“否”。

待核验主张：
GitHub Copilot Free 当前每月提供 2,000 次代码补全和 50 条聊天消息。

核对截止日期：2026 年 8 月 31 日
适用对象：个人开发者的 Copilot Free 套餐

请分别核对“2,000 次代码补全”和“50 条聊天消息”。
优先查找 GitHub 当前套餐文档、帮助文档和正式公告。
对每个来源记录标题、发布日期或核对日期、原文摘录、链接和适用范围。
如果只能证明过去成立，请明确标记为“历史上成立”，不要写成当前事实。

这段提示词不会自动保证答案正确。它的作用，是让检索任务不再含糊，也让后面的人工检查有明确对象。

四、真实案例：一句官方说法，为什么到了今天不能直接引用

现在按 SIFT 四步完整走一遍。

待核验主张是：

GitHub Copilot Free 当前每月提供 2,000 次代码补全和 50 条聊天消息。

第一步：Stop，先把一句话拆成两个主张

这句话其实包含两个独立数字：

Copilot Free 当前每月最多有 2,000 次代码补全；

Copilot Free 当前每月有 50 条聊天消息。

它们可能来自同一份旧公告，但不代表今天仍然同时成立。

还要注意两个限定词：

“当前”：要求证据能够反映 2026 年 8 月 31 日附近的产品状态；

“Copilot Free”：不能拿 Copilot Pro、学生套餐或组织套餐的额度替代。

拆到这里以后，搜索方向已经很清楚了。我们不再搜索“Copilot 好不好用”，而是分别核对两个当前额度。

第二步：Investigate，先判断手里的来源是什么

GitHub 在 2024 年 12 月 18 日发布了《Announcing GitHub Copilot Free》。

公告原文写道：

By simply signing in with your personal GitHub account, you will have access to 2000 Code Completions and 50 chat messages per month.

这是一份真实的 GitHub 官方公告。它足以证明：

2024 年 12 月发布 Copilot Free 时，官方公布了这两个额度；

这不是第三方媒体自己编出的数字。

但它仍然不能单独证明：

2026 年当前套餐继续沿用同一计量方式；

中间没有改版、调整模型或更换额度体系。

“官方来源”解决了来源身份问题，却没有自动解决时效问题。

第三步：Find better coverage，找更适合回答“当前状态”的材料

要回答当前套餐，GitHub 正在维护的《Plans for GitHub Copilot》比两年前的发布公告更合适。

我在 2026 年 8 月 31 日核对该页面时，文档显示：

Copilot Free 的内联建议每月最多 2,000 次补全；

Copilot Free 拥有一定额度的 GitHub AI Credits；

Copilot Free 和 Copilot Student 通过自动模型选择使用模型；

Copilot Free 只面向没有通过组织或企业获得 Copilot 权限的个人开发者。

这里出现了关键变化：当前文档仍能直接支持“2,000 次补全”，但当前套餐的 AI 用量说明已经采用 AI Credits 等表述，并没有继续用 2024 年公告中的“每月 50 条聊天消息”作为当前套餐表述。

因此，不能因为旧公告真实，就把两个旧数字一起复制到今天。

第四步：Trace，追溯原始语境再下结论

把两份官方资料放回各自语境：

来源能证明什么不能单独证明什么2024 年 12 月 18 日发布公告Copilot Free 发布时公布了 2,000 次补全和 50 条聊天消息2026 年仍沿用同样的聊天计量规则2026 年 8 月 31 日读取的当前套餐文档当前仍列出每月最多 2,000 次补全，并使用 AI Credits 描述部分 AI 用量旧公告中的 50 条聊天消息仍是当前额度

最后可以发布的结论应该是：

GitHub 在 2024 年 12 月发布 Copilot Free 时，官方公告写明每月提供 2,000 次代码补全和 50 条聊天消息。截至 2026 年 8 月 31 日，GitHub 当前套餐文档仍列出每月最多 2,000 次补全，套餐页对 AI 用量和模型使用则已经采用 GitHub AI Credits、自动模型选择等表述。因此，“50 条聊天消息”可以作为历史发布信息引用，不宜在缺少当前文档支持的情况下继续写成现行额度。

注意这个结论没有说“50 条已经被取消”。

当前资料足以说明旧公告不能单独代表现在，却不足以让我们凭空补出一个新的聊天额度。证据到哪里，结论就停在哪里。

五、什么才算“更好的来源”

SIFT 里的 Find better coverage，不是机械地寻找更多网页。

所谓“更好”，要看它是否更贴近当前问题。

你想确认什么通常优先寻找仍需注意当前功能和套餐当前帮助文档、套餐页、更新日志地区、账号类型和灰度范围某次发布时说了什么原始公告、发布会、完整演讲不要自动延伸到当前论文得出了什么论文原文、补充材料、勘误样本、方法和结论限制政策现在如何执行发布机关的现行文件与解释生效日期、地区和废止情况公司披露的数字财报、监管文件、原始数据表统计口径和报告周期产品是否“更好”独立测试、可复现实验、多方评价指标是否适合你的场景

原始来源也不是免检标签。

企业官网适合证明“企业当前如何描述自己的套餐”，不适合单独证明“产品效果行业第一”；论文原文适合核对研究结论，也需要查看样本、方法和局限；政府文件能证明规定内容，还要确认是否现行有效。

可以记住一个简单判断：

不是问“这个网站够不够权威”，而是问“它有没有资格证明我正在写的这句话”。

六、搜索时怎样更快追到原文

没有必要一开始就写很长的自然语言问题。检索词越接近材料本身，越容易绕开大量二手解释。

1. 从独特短语反查

如果 AI 给出了一句看起来像原文的表述，可以截取其中最独特的 6—12 个词，加英文引号搜索。

本文案例可以搜索：

"2000 Code Completions" "50 chat messages"

这一步很快就能定位到 2024 年的 GitHub 发布公告。

2. 限定可能发布原文的网站

site:docs.github.com Copilot Free plans
site:github.blog/changelog Copilot Free
site:github.com/features/copilot plans

site: 不能保证页面正确，但可以明显减少转载站和聚合内容。

3. 把时间和状态词加进去

对于会变化的产品信息，可以加入：

current
pricing
plans
limits
release notes
updated
deprecated

中文政策或公告则可以加入发布机关、文号、生效、修订、废止等字段。

4. 搜索旧说法，也搜索新术语

如果当前文档已经换了计量方式，只盯着“50 chat messages”可能一直回到旧公告。

在本文案例中，继续搜索 Copilot Free 与 AI Credits，才能发现当前套餐的描述方式已经发生变化。

这也是为什么检索不是一次命中。第一份来源经常只是告诉你：下一轮应该改用什么词继续找。

七、AI 在这套流程里最适合做什么

AI 可以显著减少整理工作，但不要让它既当回答者，又当唯一的证人。

它最适合承担四类任务：

把一段回答拆成独立主张；

为不同主张设计检索词；

对比两份已经打开的原文；

将来源、摘录、日期和结论整理成证据表。

提示词一：生成检索路线，不急着下结论

我需要核验下面的主张。请先设计检索路线，不要直接凭已有知识回答。

主张：<填写>
核对截止日期：<填写>
适用范围：<地区、版本、套餐、样本或人群>

请输出：
1. 需要分别核验的子主张；
2. 每个子主张最合适的原始来源类型；
3. 第一轮检索词；
4. 找到旧公告后，怎样继续定位当前材料；
5. 哪些情况只能标记为“暂无法确认”。

不要编造网页标题、数字和链接。

提示词二：只比较我提供的两份原文

下面是同一主题的两份材料：
A：较早的发布公告
B：当前维护的帮助文档

请只依据我提供的原文，逐项比较：
- 两份材料共同支持的内容；
- 只在 A 中出现的内容；
- 只在 B 中出现的内容；
- 术语、额度、适用对象和计量方式是否变化；
- 哪些旧说法不能继续写成当前事实。

对每个判断附上对应原句。没有证据时写“材料未说明”，不要自行补全。

提示词三：把证据压回可发布表述

请根据下面的证据表改写结论。

要求：
- 当前来源直接支持的内容，可以写成确定事实；
- 只被旧资料支持的内容，标记为“历史上成立”；
- 来源没有说明的内容，写成“暂无法确认”；
- 不把“没有找到”改写成“已经不存在”；
- 保留日期、地区、版本和套餐范围；
- 每句话后标注对应来源编号。

证据表：
<粘贴>

这里有个很实用的习惯：让 AI 输出“材料未说明”。

很多错误不是模型看错了原文，而是它觉得回答不够完整，于是用常识或旧知识把空缺补上。允许它停下来，反而更可靠。

八、保留一张证据表，别只保存一堆书签

浏览器里开了十几个标签页，并不等于检索结果可以交付。

真正有用的是一张能回答“哪份材料支持哪句话”的表：

| 编号 | 待核验主张 | 来源与链接 | 发布/核对日期 | 原文摘录 | 适用范围 | 状态 | 可发布表述 |
|---|---|---|---|---|---|---|---|
| S1 |  |  |  |  |  | 当前确认/历史成立/部分成立/暂无法确认/冲突 |  |

本文案例可以这样记录：

编号待核验主张来源时间状态S1发布时有 2,000 次补全和 50 条聊天消息GitHub 2024 发布公告2024-12-18历史上成立S2当前仍有每月最多 2,000 次补全GitHub 当前套餐文档2026-08-31 核对当前确认S3当前仍固定为 50 条聊天消息GitHub 当前套餐文档未沿用该表述2026-08-31 核对暂无法按旧说法确认

书签只能告诉你“我看过这些页面”。证据表才能告诉下一位读者：结论是怎样从原文里得出来的。

九、什么时候可以停止搜索

检索很容易变成无止境地开标签页。SIFT 的第一个动作 Stop，也包括在过程中停下来重新确认任务。

低风险问题通常满足下面几项，就可以结束：

已找到适合当前时间和场景的直接来源；

关键主张都能对应到具体原文；

日期、版本、地区和对象没有错位；

不同来源之间没有影响结论的明显冲突；

对无法确认的部分已经降低语气，而不是继续猜。

如果遇到以下情况，就不应该只靠普通网页检索结束：

医疗、法律、投资、税务等高风险决策；

原始资料互相冲突；

关键数据只能在付费报告或缺失附件中找到；

结论会影响他人权益或造成不可逆损失；

需要行业资质才能正确解释的专业材料。

有时候最准确的交付不是一个“是”或“否”，而是把目前能确认的边界写清楚。

十、五个看起来认真、其实不够可靠的检索习惯

只看搜索结果摘要

摘要可能被截断，也可能来自页面旧版本。它适合帮助你选页面，不适合直接当引文。

给了三个链接，就当成三份证据

如果三篇文章都引用同一份公告，证据链仍然只有一条。应该继续追到共同来源。

官方页面支持产品存在，就顺便相信效果宣传

“提供某功能”和“该功能效果最好”是两个主张，需要不同证据。

换一个模型得到同样答案，就算交叉验证

模型可能引用相同网页、相同训练数据或同一条过时说法。模型之间的一致不是来源独立。

搜不到反例，就写成已经证实

没有找到反驳，不等于已经证明。先确认正面证据是否直接、当前且范围一致。
