Is Cursor worth it?

Yes, with one condition: set a spend limit on day one. A flat $20 buys a genuinely good editor, and the metered usage on top is fair but unbounded. I paid Cursor $510.70 across eleven months before cancelling, a third of it metered charges I could have capped and never did, and the editor was never the reason I left.

What does Cursor actually do in 2026?

Open Cursor today and you do not land in a code editor. You land in an agent.

That screenshot is the default view on a current install. A prompt box, a model selector, a “Plan New Idea” button, and a hint that /shell runs terminal commands. No file tree in the centre, no open buffer, no cursor blinking in code.

The 2026 reviews have caught up with this and lead on agents. What has not caught up is Cursor’s reputation, which is still “VS Code with good autocomplete”, and several of the older published reviews describe exactly that product. The centre of gravity has moved from typing alongside an assistant to briefing one, which puts Cursor closer to a terminal agent than most people expect.

The VS Code lineage is still underneath. It remains a fork, so your extensions, keybindings and settings carry over, and that is still the strongest practical argument for choosing it over a tool that asks you to abandon your setup. You can drop back into a normal editor window whenever you want.

What sits on top is now a full agent stack: skills you define, hooks, a plan mode, and Composer as the in-house model alongside frontier models from other labs. The pitch is that you brief work, review a result, and stay in one window while doing it.

The slash commands tell you what it wants you to do

A product’s hint text is an honest signal of where its makers think the value is, and Cursor cycles through several on that empty home screen. /shell runs terminal commands without leaving the window. /plan switches on Plan Mode, described in the app as a way to improve agent execution. /create-skill builds a reusable skill, with the app framing skills as the way you customise Cursor around your own workflows.

None of those are editor features. They are agent-management features, and they are what the product leads with before you have typed anything. Two years ago the equivalent hints would have been about autocomplete.

How it gets context

The prompt box advertises two symbols, and they carry most of the workflow. @ pulls in context, letting you point the agent at specific files, folders, docs or past chats rather than hoping it finds them. / reaches your skills.

This is the meaningful difference from a terminal agent that simply reads whatever it decides it needs. Cursor makes context an explicit act. You choose what goes in. Whether that is a strength depends on your temperament: it is more control and more typing, and it means a badly-scoped prompt is your fault rather than the model’s.

A model selector sits under the prompt, showing Composer 2.5 Fast on my account with a lock icon beside it. On the free tier the better models are visible but gated.

What the paid tiers actually add

The pricing page is specific about the jump from free to paid, and it is mostly about limits rather than capability. Individual buys extended limits on the agent, generous limits for Grok and Composer, access to frontier models, and MCPs, skills and hooks. Cloud agents are included. Bugbot, the agentic code reviewer, arrives on usage-based billing.

That last phrase is the pattern in miniature: a headline feature listed under a $20 plan that the $20 does not cover. It is available to you, and it bills separately.

Teams at $40 per user adds shared context across a team, a marketplace for internal rules and skills, usage analytics, a team-wide privacy mode and SSO. Cursor also states that with privacy mode enabled, code data is not used for training by them or their model providers, which is the answer most people working on client code will want before installing anything.

What you can do about it

The control I needed existed on the plan I was already paying for, and I never used it. Cursor’s spend-limit docs are unambiguous: on Pro, Pro Plus and Ultra you set a monthly cap on on-demand usage from the Spending tab in your dashboard. Not an enterprise feature, not a support ticket. A field I could have filled in during my first week.

That reframes my own story, so I will say it plainly rather than bury it: a meaningful share of my $170.70 is my fault. I assumed the subscription was the cost, did not read the billing docs, and noticed the charges only when the card statement arrived. If you take one thing from this review, make it that field.

The other lever is model choice. The expensive lines on my invoices were the reasoning-heavy models, and the cheaper ones barely registered. Matching model to task is the single biggest thing under your control, and the interface makes it a one-click change.

Who is Cursor for?

Developers who want AI in an editor they already know. The VS Code foundation means no migration cost, and that is a real advantage over tools that ask you to change how you work.

People who code moderately and predictably. My five flat $20 months are the proof this works. If your usage sits inside the allowance, $20 buys a lot.

Teams that want code review built in. The $40 tier adds Bugbot, shared context and SSO, which is a coherent package rather than a price bump.

People working under a confidentiality obligation. Cursor states that with privacy mode on, code data is not used for training by them or their model providers, and the team tier can enforce it across everyone rather than trusting each person to tick a box.

Anyone who wants model choice in one place. Frontier models from several labs behind one subscription is genuinely convenient.

Not for heavy agent users, or anyone who needs a predictable bill. This is the group I fell into. If you delegate large tasks all day, the meter runs, and you will find out how fast only in arrears.

The dividing line is not seniority or language or project size. It is whether your usage is bursty. A steady drip of small edits sits comfortably inside the allowance for $20 a month. A habit of handing over large, multi-file jobs several times a day does not, and no plan on the page reliably contains it.

If the honest description of your situation is that there is no codebase yet, then the category is wrong rather than the plan. An app builder will get you a working prototype faster than any editor will, and Lovable is the one I have put through a measured build.

If you are unsure which side you fall on, the free tier answers it faster than any review can, including the rest of our picks. Use it for a fortnight on real work and watch how quickly you meet the limits. That tells you more about your future bill than the plan cards do.

The good

It was worth $20 for five months straight

The most honest evidence I can give is my own invoice column. March through July 2025 read $20.00, $20.00, $20.00, $20.00, $20.00, with no usage charges attached. During those months Cursor did everything I asked at list price, and I would have told you it was excellent value. That period is why the rating here is not lower.

Five consecutive clean months is not a trial. It is long enough to build habits, ship real work and form a settled opinion, and my settled opinion at the time was that $20 was cheap.

The VS Code foundation removes the switching cost

It is a fork, so extensions, themes, keybindings and settings come across intact. Compared with adopting a terminal agent, where you rebuild your habits from scratch, this is the least disruptive way to get serious AI help into an existing workflow. That advantage is structural and no amount of billing frustration takes it away.

Adopting it is a download rather than a migration, with no need to defend a tooling change to colleagues who like their setup. When I left, this was the thing I actually missed.

Model choice in one subscription is genuinely useful

My invoices name the models I was calling: Claude Sonnet and Claude Opus variants, alongside Cursor’s own Composer. Being able to pick a model per task, without holding separate subscriptions, is convenience you notice daily.

It also has a cost benefit if you use it deliberately. Each usage line on my Cursor invoices names its model and its call count, so the per-call cost falls straight out of the arithmetic:

The free tier lets you reach the real product

Hobby costs nothing and asks for no card, and it gives you limited agent requests plus Composer access rather than a crippled demo. My cancelled account still sits there. Plenty of tools in this category gate the actual experience behind a card; this one does not.

The agent stack is deeper than its reputation

Skills, hooks, plan mode, cloud agents and a /shell command add up to something you can shape around your own workflow. If your mental model of Cursor is “VS Code with autocomplete”, it has moved a long way past that.

The tiled agent panes are the detail that gave me most pause about leaving. Being able to run several agents and watch them side by side in a graphical window is something a terminal genuinely does worse, and if parallel delegation is how you work, that interface is a real argument for staying.

Team features are a real package, not a price bump

At $40 per user the Teams tier adds Bugbot for agentic code review, shared team context, usage analytics and SSO. For a team already standardised on VS Code, that is a coherent step up rather than the usual enterprise tax.

The bad

A third of what I paid Cursor was not the subscription

Of the $510.70 I paid Cursor across eleven months, $170.70 was on-demand billing. That is 33% of my total spend arriving after the fact, on a product whose headline price is $20. Nothing about it is hidden: the pricing page states that on-demand usage continues after your included amount and is billed in arrears, and the docs set out the rates.

The complaint is about emphasis rather than concealment. The card says $20 in large type and the metering is a sentence in an FAQ, so the number that anchors your expectation is the one least likely to match your invoice.

The $60 plan ran out in about a week

I upgraded to Pro Plus specifically to stop the overage. The larger allowance was gone in roughly a week of normal work, and the on-demand charges resumed on top of the higher subscription. Paying three times more did not buy predictability, which is the thing I was actually trying to purchase.

That is the moment the product lost me, and it is worth being precise about why. I did not object to paying more for more. I objected to paying three times more and still not knowing what the month would cost. An upgrade that raises the floor without lowering the variance solves the wrong problem.

Two of my last four months cost more than $100

October 2025: $159.22. November 2025: $110.00. Those are not stories about a runaway script or a mistake, they are ordinary months. When a $20 tool bills $159, the number on the plan card has stopped being useful for budgeting.

October is the clearest example of how the charges arrive. Four separate hits: $20 for the old plan, $40 of usage, $60 for the upgrade, then another $39.22 of usage six days later. No single charge looks alarming. The sum is eight times the advertised price.

Metered API rates lose to a flat cap once you are heavy

I assumed for months that Cursor was taking a cut on the Anthropic models my invoices show me calling. It is not. The billing docs are clear that third-party models on individual plans are charged at the model’s API price, and the $0.25 per million token Cursor Token Rate applies only to Teams and Enterprise. I was paying list.

That correction sharpens the real point rather than removing it. Metered API pricing is honest and it is also unbounded, so at high volume you are competing against capped subscriptions from the labs themselves. Being precise about the arithmetic, because it is easy to flatter my own decision here: my two heaviest Cursor months carried $79.22 and $50.00 of metered usage on top of the subscription, for totals of $159.22 and $110.00. Claude Max 5x bills me $110 a month once tax is added. The gap is not that one is cheap and the other expensive. It is that one has a ceiling and the other does not.

You carry the context burden

The prompt box makes context an explicit act. @ points the agent at files, folders or symbols, which is more control than an agent that decides for itself, and also more work. Every session you are choosing what goes in.

That has a real failure mode: a badly-scoped prompt produces a confidently wrong answer, and the fault is yours rather than the model’s. A terminal agent that reads the repository on its own removes that step and the mistake with it. Which trade you prefer is temperament, but it is the one place where Cursor asks more of you than its rivals do, and it is not a billing complaint.

What I got wrong, and what I am not claiming

Three criticisms I had drafted did not survive checking Cursor’s own documentation, and cutting them is more useful to you than keeping them. I believed the Pro Plus and Ultra prices were unpublished; they are, at $60 and $200. I believed Cursor took a margin on third-party models; on individual plans it charges the model’s API rate. I believed the plan I bought had been renamed away; “Cursor Pro Plus” at $60 is still exactly that.

The one that stings is the spend limit, because it was available on my plan the whole time and I never opened the Spending tab. A meaningful share of my $170.70 is a documented control I did not use.

The score gap with my whether Claude Code is worth it also invites an inference I want to head off: it is not a judgement that Cursor writes worse code. In eleven months it never produced a wrong-answer failure costly enough that I still remember it. I cannot give you a rigorous capability verdict either, because I did not run the two tools side by side on identical tasks. What I have is eleven months of invoices, and the 4.2 reflects cost behaviour, which is the axis I can actually evidence.

Final word

The short version of this Cursor review: a good editor attached to a pricing model that punishes the people who use it most. For five months it was the best $20 I spent on software, and I would still recommend it at that level without hesitation. The trouble starts precisely when the tool succeeds, because the more work you delegate, the further your bill drifts from the number that sold you the plan.

If you are a moderate user, buy it and enjoy it. If you are heading toward daily agent work, do the arithmetic first, because I did not, and eleven months later I had paid $510.70 for a $20 subscription and moved on.

The version of this review I expected to write was harsher, and checking Cursor’s documentation made it milder twice over. The first seven months are a good tool at a fair price. The last four are a cautionary tale about a meter I could have capped with one field and did not. Both halves are true, and which one you get depends on how much you delegate and whether you read the billing docs before the card statement.
