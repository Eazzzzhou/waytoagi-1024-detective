## 到件后的复核顺序

1. 先登记材料来源、文件哈希、获取时间与只读原始响应。检查 Schema 与引用结构，但结构正确不能证明事实正确。
2. 先阅读原始问题、身份依据与来源原文，记录丙的独立判断和时间；再对照已保存回答及甲乙预期，保留分歧双方的依据。
3. 逐条检查所有引用，不抽样替代完整核对。打开真实来源核对定位、原句和上下文；若网页已变更，分别记录“当前网页”与“保存原文”，无法核实标为不可判定。
4. 按 claimId 对照 relations 与回答措辞，核对支持范围、时间、版本、套餐、条件和来源独立性。官方说明只能证明其宣称，不自动证明实际效果。
5. 在实际页面检查表达、引用跳转、错误、历史属性与限制是否可见；浏览器不可用时，页面实操项维持未验证。
6. 分类派单；丙仅修展示问题，甲处理事实／来源／翻译，乙处理持久化／接口／运行。共享语义先三方对齐，不改原始快照掩盖问题。
7. 修复后登记新执行／快照标识或前端版本，重查问题与关联影响，保留旧记录。没有复验不能关闭问题。
