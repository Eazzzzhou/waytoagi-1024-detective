## 交互规则

- 提交与操作有同步防重锁；网络失败不自动重发 POST。相同问题重试保留 Idempotency-Key；换问题或已接受后的新提交建立新键。
- PENDING／RUNNING 每次读取完成后等待 2 秒再读，阶段来自后台；其他状态停止正常轮询。
- 网络失败按“首次请求 + 最多 3 次自动重试”执行，间隔 2 秒；成功即重置失败计数。HTTP 错误、无效 JSON 和 Schema 失败不冒充网络问题，不自动重试。
- 失败保留最后成功加载的数据和独立 readAt；任务 updatedAt 继续只表示服务端更新时间。读取停止后明确提示手动刷新。
- identity／retry 的 HTTP 409 触发当前调查重新读取，持久显示数据已变化提示，不重放原操作；提示不会被成功 GET 清除，身份表单卸载后提示仍在父组件。
- 重试权限来自后台 retry.allowed，不根据业务错误代码推断。读取失败或刷新尚未完成时暂停确认／重试，避免用旧控制条件操作；成功读取后恢复按后台规则判断。
- 详情与快照 GET、三类 POST 在卸载时取消；旧响应即使忽略 AbortSignal 后才返回，也不会覆盖新调查。刷新会取消前一轮读取与计时器。
- 按服务端 resultSnapshotId 读取快照，展示前再次匹配快照 ID 与 investigationId。非 SUCCEEDED 状态指向的已有快照标为历史材料；重新读取失败时注明保留上次快照及读取时间。
- 当前契约没有 execution/attempt 对应的快照字段，前端不私加字段或自行推导；本轮成功关联依赖服务端原子发布维护的 status + resultSnapshotId，另做双 ID 检查。
