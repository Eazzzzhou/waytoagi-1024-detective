# 合作者对接与缺失项清单

核对日期：2026-10-25。按用户要求集中列出目前需要合作者或实际参与者补齐的内容；任务进度仍只在[乙丙方案](乙丙开发与验收方案.md)维护，工程验证只见[当前状态](README.md)。本文件不保存凭据值。

## 已有实现与 Git 过滤

SearchPro 搜索入口和凭据读取代码**已经存在**：项目将腾讯云 SearchPro 作为“元宝搜索”入口，从服务端读取 `TENCENTCLOUD_WSA_APIKEY`，也支持 `TENCENTCLOUD_WSA_APIKEY_FILE`。主模型是另一条 Chat Completions 通路，读取 `MODEL_BASE_URL`、`MODEL_NAME`、`MODEL_API_KEY`；现有 DeepSeek 模板和两条 API 路径保持不变，不改成同一个腾讯元宝 API。

本机检查发现，上述主模型变量、SearchPro 两种凭据变量及第二模型变量均未配置。`.gitignore` 确实过滤 `.env`／`.env.*`（保留 `.env.example`）及 `.cache/`。这能解释本地配置和缓存不随 Git 传递，但不能证明合作者此前已经配置成功。凭据应通过双方约定的私下方式配置到服务端环境，不强行加入仓库；现有 `.env` 的数据库设置需保留，按[模板](../.env.example)合并缺少项。

## 对接后执行顺序

1. 合并服务端本地配置，保留数据库设置；运行 `npm run services:check`。该命令只报告配置存在／缺失与独立模型身份，不输出密钥、URL 或路径，不发网络请求；主模型配置或搜索凭据缺失时返回非零，文件方式只检查存在、不校验文件内容。配置存在也须正式调用核实权限、额度和可用性。
2. 按根 README 启动 Web 与独立 Worker。先用一条范围明确的客观问题走正式调查，再使用其真实快照和实际使用者条件创建建议请求；接口和可执行 Schema 见[HTTP 边界](甲与乙丙协作边界.md#http-边界)，不灌入案例参考或合成成功结果。
3. 对已创建的真实建议请求运行只读留档命令：`npm run advice:capture -- <investigationId> <requestId> .cache/acceptance/<唯一文件名>.json`，默认读取本地 3000 端口，可用末尾参数指定本地 origin。命令只 GET，轮询至终态或观察超时，保存请求／建议、绑定快照、客观回答及 hash；同名文件拒绝覆盖。观察超时保留活动状态，不把它改成业务失败；hash 只记录本次观察，不能单独证明此前未被修改，也不代替语义复核。
4. 用既有 D1 CLI 和唯一 run-id 追加正式三案对照；人工语义复核原位记录。缓存 JSON 是本机诊断依据，正式案例记录继续遵守 runs 约定。
5. 真实服务及页面可用后，组织 E5–E7 的实际参与者和录制。凭据、真实运行或真人尚缺时，阶段 5／6 和 E3／E4 保持未验收；可以先完成独立工程与工具准备。

无需等合作者才能完成的工程适配、故障回归和记录工具可以继续开发；正式服务成功、页面联调、独立复核及真人试用不能靠这些准备工作代签。
