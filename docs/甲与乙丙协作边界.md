## 公共工程约束

- src/contracts 是唯一可执行契约。前端／Provider 不复制 DTO；未知用 null，空集合用 []；字段语义变化需对齐读写方和兼容策略，历史快照不覆盖。
- Web 做短请求与任务控制；独立 Worker 执行长任务。浏览器不能导入 server、Prisma、Node；Worker / contracts 不依赖 Next 请求运行时；正式源码不能导入 tests 或 cases。
- 队列使用数据库时间、SKIP LOCKED、执行令牌、租约／心跳、截止和有限重试。失效执行不能续租、推进或发布；快照、回答、成功状态在同一受令牌保护事务提交。
- 调查仍是一调查一 Job。建议使用独立 AdviceRequest（type=ADVICE）及 AdviceExecutionAttempt，同调查幂等键唯一，绑定不可变快照及真实条件；不复用调查 Job 或重置失败计数。建议队列已具备数据库时间、领取／续租／截止／回收、有限自动重试和原子发布；预算在创建时固定，幂等重提不重启终态。补查、对外取消、建议手动重试和历史切换不属本轮必做。
- 身份确认与手动重试携带 expectedAttemptCount；409 重读状态，不自动重放。手动重试每调查最多两次，每次只加一次机会，不清零历史。
- 迁移只追加，不用 db push；测试仅使用独立测试库随机 schema。Repository 写前／读后校验，数据库列与 JSONB 一致，错误不回退为虚构结果。
- 快照不可变，后续版本指向同调查前一版本。新回答 quotes 必须逐字符匹配本快照 READ 原句；历史缺 quotes 的回答只读兼容。结构检查不证明语义支持。
- 密钥不进浏览器、仓库、快照或 generationConfig；日志避免原问题、凭据和 Provider 原始正文。当前本地 Host／Origin 检查不是认证或公共部署方案。

## HTTP 边界

请求／响应字段以 src/contracts/http.ts 和 src/server/http/api.ts 为准，错误统一为 {error:{code,message}}，与调查业务 error 分开。JSON 请求体上限 32 KiB。

| 已实现接口 | 作用 |
|---|---|
| POST /api/investigations | Idempotency-Key 幂等提交；202 返回 investigationId / reused |
| GET /api/investigations/:id | 状态、阶段、失败、身份确认需求与重试控制 |
| POST /api/investigations/:id/identity | 当前等待尝试的真实身份确认 |
| POST /api/investigations/:id/retry | 符合失败及预算规则的恢复 |
| GET /api/snapshots/:id | 已校验快照与 answers；当前不含 Advice |
| POST /api/investigations/:id/advice-requests | Idempotency-Key 幂等创建建议任务，202 返回 adviceRequestId / reused；快照须属于路径调查，同键不同载荷为 409 |
| GET /api/investigations/:id/advice-requests/:requestId | 查询持久化任务状态及结果；成功时读取 Advice，其他状态不返回虚构建议；跨调查或不存在为 404 |

建议请求／响应的唯一可执行定义为 src/contracts/advice-request.ts；状态与结果共用查询接口，条件不足与系统失败分开。同一快照不同条件可有独立任务，同键重提读取原任务而不重置状态。AdviceRepository 校验写入／读出、快照归属、请求条件与结果一致性；新发布的完整结果 hash 也在读取和重复发布时复核。存储方法本身不推进任务，正式发布只能通过 PostgresAdviceQueue.complete，在有效执行令牌事务内关联 Advice／条件不足、尝试记录及终态。Worker 离线保持 PENDING；已接入主模型建议执行、原句核查及条件不足分支，无主模型配置则 PROVIDER_NOT_CONFIGURED／FAILED。正式页面已调用建议通路，本轮 Dify 真实生成／发布／读取及刷新已验证；整体内容质量仍待验收，建议读取错误不遮住客观回答。快照版本链也不代表补查已实现。

建议状态通路为 PENDING → RUNNING → SUCCEEDED／INSUFFICIENT_CONDITIONS／FAILED；可重试错误、超时、租约丢失及内部关闭在固定预算内回到 PENDING 并退避，耗尽则 FAILED。INSUFFICIENT_CONDITIONS 是终态业务结果，不写系统 error 或 Advice；新条件需创建新请求。执行接入类型和校验位于 src/worker/advice-handler.ts、src/server/queue/advice-contracts.ts，实际模型请求已消费 signal；真实服务取消行为仍需联调，不能仅以替身证明。

建议 HTTP 沿用本地 Host／Origin 边界；服务端 canAccessAdviceInvestigation 策略可拒绝请求并返回 403，建议队列也提供加载及发布前的同步可信快照策略，但默认仍为共享本地工作区。当前不存在用户账号／所有者模型，路径调查归属校验不是用户身份认证，不声称已实现多用户权限。正式认证接入后须由可信服务端统一提供 HTTP 与 Worker 策略并保证数据库归属一致，不能相信请求自报的所有者，也不在数据库事务内调用远程鉴权。

## 核查与展示的共同要求

- 区分事实、官方宣称、使用者报告、观点、归纳；原文和译文分开。官方 benchmark 不是独立实测，个体经验不是群体共识。
- 原句最多300字符，保留 URL、获取日期和定位。READ 要有实际原文、定位、内容 hash；搜索摘要不能升级为原文，失败／限制不等于没有讨论。
- 同作者、同实验、转载、翻译或共享上游不增加独立支持；UNKNOWN 不计独立。判断须针对具体主张、关系和范围，不能机械数 originGroupId。
- 保留版本、套餐、地区、时间、冲突及缺口；未列出不等于不存在，有限检索不证明全网没有。历史快照标版本／时间。
- 客观问题直接回答；建议使用真实条件，四档只用于建议；条件不足不遮住客观回答，不引入无证据事实。
- 不调查时政或具体个人隐私；作者归属只保留必要公开信息。负面措辞限定实际范围，不作无依据的欺诈定性。
- 材料、参考、复核隔离；系统输入仅固定问题及必要真实身份依据，不回灌预期结论。确认和独立复核只能由实际参与者署名；已看参考不能声称盲评。案例写法见[案例规范](../cases/D1-案例规范.md)。
