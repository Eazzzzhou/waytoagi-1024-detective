## 已实现

- models：Node24原生fetch调用非流式Chat Completions JSON mode，强制本地Zod解析，拒绝空内容、拒绝、截断、非法JSON/结构。JSON语法/结构错误至多一次格式修复，失败与修复调用都记录，截断不伪装成功。支持超时与Worker取消，不保存隐藏思考或密钥。实际响应模型、usage、耗时与调用目的进入快照。
- verification：按原问题提取原子主张，按保存原句判断支持/反驳/上下文；区分官方宣称、个案报告与事实，保留版本、套餐、日期和条件差异。不确定保留INSUFFICIENT，可比作用域的相反证据才构成DISPUTED/冲突。
- 同源：使用明确upstreamUrl、采集来源组和已保存的实际重定向URL；www别名还要求同路径和原句hash相同。官方出版方的语言/子域同组，不算独立实验。不同域名、相同模型意见或无关联短引相同均不能证明来源独立。
- answer：模型选择直接回答问题的已核验主张，正文由这些主张及适用范围确定性生成，不另作事实扩写。先校验引用ID/READ状态/主张关系，再另做原句语义支持检查；失败段落移除，关联主张降为INSUFFICIENT、关系转UNCERTAIN并留缺口。quotes由程序复制已保存原句，最终assertAnswerReferences逐字符核对。模型只接收保存短引，较长上下文和译文仍存页面但不进入核查/回答证据提示。语义检查仍是模型判断，不保证永不误判，真实运行另作下述可读原句核对。
- handler：A1身份→元宝/公共搜索→原文→核查→回答，只返回COMPLETE/AWAITING_CONFIRMATION，Worker保持租约、失败与事务发布职责。
- 补查：只针对影响回答的未决主张评估价值；最多1个查询（分别记录元宝与公共搜索调用）、2个新增原文、20秒采集预算；到限/失败保留缺口并完成，不凑来源数量。
- 可选复核：第二模型先仅按问题/身份/原证据独立判断，再对照初稿；主模型按具体证据逐项采纳/拒绝并落实修改。没有有效纠正如实记录。当前用户暂不配置第二模型，真实状态NOT_CONFIGURED，不声称已完成独立模型复核或精度提高。

唯一共享定义仍为src/contracts，兼容增补可选verificationAudit（调用、独立评估/裁决理由、语义检查、补查预算），旧快照可读。采纳建议必须有原证据；审计引用经共享Schema验证。无平行生产DTO、无数据库迁移。实验方法复用原目录research/core-round1/A2，不把实验JSON充作生产结果。
