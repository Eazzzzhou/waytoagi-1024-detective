# 案卷｜队友交接包

版本：v2.2 · 2026-10-24。甲负责数据获取与交叉验证核心；乙负责真实案例 D1；丙负责展示口径 D2。两位队友互相复核，各自对主交付负责。完整模块输入与输出在[派单](策划/迭代与任务派单.md)。

## 收到后 10 分钟

1. 打开[任务派单](策划/迭代与任务派单.md)，找到自己的 DRI、交付卡与截止。
2. 看[附录 A：案例形状](策划/附录A-案例样例.md)和[附录 B：表达形状](策划/附录B-口径样例.md)，明确需要交出的成果；样例来源全为假，真实任务必须替换。
3. 在团队群报一句：“我做 D?，预计 ? 交第一版。”群和 T0 尚待核心确认时，先准备材料，待公布后补报。

## 提前知道这些

- 核心会提供六个候选产品与问题意图；T0、候选、共享目录及沟通群统一登记在派单的启动信息，目前待核心补齐。
- 默认 D1 首条 T0+3h、三条齐 T0+6h、独立复核 T0+12h；D2 提纲 T0+3h、草稿 T0+6h、定稿 T0+12h。绝对时间待 T0 确认，遇硬截止由核心统一重排。
- 内部首次提交目标：2026-10-25 14:30；既有官方核查资料记录提交截止 16:00。T0 不是文档创建时间。
- 交付物、数量和验收固定；研究方法、工具与工作顺序自主。案例只需六项材料，不要求错误分类、评分系统或技术实现。
- 元宝必须实质参与核心检索；海外社区是重要来源，平台按线索拓展。读取失败保留线索，不说“没人讨论”。
- 客观搜查直接回答；只有用户需要适配建议时才使用四档。两种回答共用查证链路。
