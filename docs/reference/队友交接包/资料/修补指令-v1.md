### 2.2 `策划/核查与交接规范.md`

**A. 在「## 五项共同要求」之前插入：**

```markdown
## 红线（任何交付都不得越过）

1. **不碰时政**；不涉及具体个人的身份、联系方式与私德。
2. **引用三件套**：原句 + 链接 + 抓取日期，缺一不可；不整段转载，超过 300 字只摘关键句并给链接。

4. **官方宣称与第三方实测必须分栏**；官方 benchmark 不得当作独立实测，转载不得当作独立来源。
5. **读取失败 ≠ 没有讨论**：必须写"读取失败（403 / 超时 / 无权限）"，不得写成"没有相关信息"。
```

```markdown
每个案例**必填 6 项**（其余随案例补充）：

1. 案例 ID（`A-01` 起）与产品、版本/套餐；
2. 用户问题原话 + 回答意图（客观搜查 / 适配建议）；
3. 证据列表：URL + 原句 + 站点 + 发布时间 + 作者或身份线索；
4. 每条证据对哪个主张是支持 / 反驳 / 无关；
5. 冲突点与缺口（未取得、读取失败、确实没有）；
6. 核查时间与核查人。

**明确不要求**：错误分类体系、置信度百分比、评分表。表达形式自选。
```

1. 这句话是原话、译文，还是归纳？
