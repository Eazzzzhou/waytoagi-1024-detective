# 业务数据契约 · 公共工程交接版

唯一可执行定义在 `src/contracts/index.ts` 的导出中，每个对象都有 Zod Schema 和 `z.infer` 类型。所有对象采用 strict 模式：拒绝未知字段，避免把模型额外输出、凭据等默默保存。字段语义改变需提升契约版本并迁移读写方，不能覆盖历史快照。

通用约定：ID 使用 UUID；时间是含时区 ISO 8601 字符串，数据库用 timestamptz(3)，建议统一输出 UTC 毫秒精度；未知值明确用 `null`，集合无项目用 `[]`，不填“未知”字符串伪装为数据。URL 只接受 HTTP(S)，结构校验不代表链接已访问或可安全抓取。未来来源获取实现仍须处理 URL 安全、重定向和实际访问状态。

## Investigation

| 字段 | 含义 |
|---|---|
| id | 唯一调查 ID，数据库生成 UUID |
| question | 用户原始问题，仅去除首尾空白，1–4000 字符 |
| status | PENDING / RUNNING / AWAITING_CONFIRMATION / SUCCEEDED / FAILED / CANCELLED |
| stage | CREATED / IDENTITY / RETRIEVAL / SOURCE_FETCH / VERIFICATION / ANSWER / COMPLETED；真实执行阶段，不是模拟百分比 |
| error | null 或 `{code, message, retryable}`；message 只能包含可对外暴露的脱敏信息 |
| createdAt / updatedAt | 创建与最后更新时间 |
| startedAt / completedAt | 真实执行开始、终态时间；未发生为 null |
| resultSnapshotId | 当前发布的结果快照 ID，未产生为 null |

失败状态必须带 error；终态必须带 completedAt；成功必须处于 COMPLETED、指向快照且没有 error。数据库复合外键禁止指向别的调查的快照。记录创建不代表开始执行，本阶段存储默认 PENDING/CREATED。

错误码包括 `PROVIDER_NOT_CONFIGURED`、`CAPABILITY_NOT_IMPLEMENTED`、`INVALID_INPUT`、`PROVIDER_FAILED`、`STORAGE_FAILED`、`LEASE_LOST`、`TASK_TIMEOUT`、`WORKER_SHUTDOWN`、`LEASE_EXPIRED`、`IDEMPOTENCY_CONFLICT` 和 `UNKNOWN`。目前所有真实能力占位实现均抛出 `CapabilityError`，detail 为 `PROVIDER_NOT_CONFIGURED`，不返回成功结果；错误重试语义见 [异步任务队列与租约恢复机制](异步任务队列与租约恢复机制.md)。

## ProductIdentity

| 字段 | 含义 |
|---|---|
| name | 产品名称 |
| officialWebsite | 已识别官网或 null |
| version / plan | 本次核查的版本、套餐；无法确认则 null |
| confirmationStatus | UNRESOLVED / NEEDS_CONFIRMATION / CONFIRMED |
| confirmationBasis | 身份确认依据数组，每项 `{url, excerpt, retrievedAt, reason}` |

CONFIRMED 至少需要官网和一条依据。依据 excerpt 最长 300 字符，为原文关键句，不是模型归纳。Schema 只验证结构与引用完整性，不自动判断依据是否足以确认产品。

## Evidence

| 字段 | 含义 |
|---|---|
| id / sourceUrl | 证据 ID 与直达来源 URL |
| originalExcerpt | 原文关键句，最多 300 字符；未读原文为 null |
| translation | 译文，与原文分开；未翻译为 null |
| originalLocation | `{kind, locator, context}` 或 null；kind 为 TEXT / COMMENT / PAGE / TIMECODE，locator 是段落、评论 ID、页码或视频时间等可人工复定位描述，context 为必要上下文 |
| metadata | 来源元数据，见下表 |
| retrievedAt | 实际获取或尝试获取的时间，失败时表示尝试时间 |
| readStatus | READ / NOT_FETCHED / FAILED / RESTRICTED / SNIPPET_ONLY |
| readError | 实际失败或限制原因；原因不明明确为 UNKNOWN，不臆造 403 等错误 |
| contentHash | 已取得原始内容的 SHA-256 小写十六进制 64 字符；未读取为 null |

READ 必须有原句、定位、hash，且无 readError；FAILED / RESTRICTED 必须带原因。其他读取状态不能填原句、译文、定位和 hash。搜索摘要只放 RetrievalRecord 的 snippet，不升级为原文证据。hash 由未来获取模块对原始内容计算，Schema 只能检验其格式。

| metadata 字段 | 含义 |
|---|---|
| title / siteName / author | 来源标题、站点名、必要的公开作者名或账号；缺失为 null |
| publishedAt / language | 来源发布时间与原文语言；缺失为 null |
| sourceType | OFFICIAL / COMMUNITY / THIRD_PARTY / UNKNOWN |
| contentKind | FACT / OFFICIAL_CLAIM / USER_REPORT / OPINION / UNKNOWN；内容性质与原文／译文的表达形式分开 |
| productVersion / plan | 此来源适用的版本和套餐 |
| upstreamUrl | 已知上游原始来源，未知为 null |
| independence | UNKNOWN / INDEPENDENT / SHARED_ORIGIN；跨平台不自动独立 |
| originGroupId | 已识别的共同源头分组，SHARED_ORIGIN 必填 |
| independenceReason | 判定独立或同源的理由；非 UNKNOWN 必填 |

这些字段仅记录判定与依据，没有实现独立性算法，也不计算支持票数。

## Claim 与 EvidenceRelation

| 对象 / 字段 | 含义 |
|---|---|
| Claim.id / statement | 主张 ID 与单条原子主张 |
| Claim.kind | FACT / OFFICIAL_CLAIM / USER_REPORT / OPINION |
| Claim.verificationStatus | UNVERIFIED / SUPPORTED / REFUTED / DISPUTED / INSUFFICIENT |
| Claim.verificationReason / scope | 判断理由与适用范围；范围未知可为 null |
| EvidenceRelation.claimId / evidenceId | 当前快照内的主张、证据 ID |
| EvidenceRelation.relation / reason | SUPPORTS / REFUTES / CONTEXT / IRRELEVANT / UNCERTAIN，以及理由 |

关系不可悬空，同一主张／证据对不可重复；只有 READ 证据可以 SUPPORTS / REFUTES。主张的原子性、判断理由和结论正确性由甲的实现及人工复核负责，Schema 不代替核查算法。

## RetrievalRecord

| 字段 | 含义 |
|---|---|
| id / provider / query / calledAt | 检索调用 ID、提供方名称（含元宝）、实际查询词、调用时间 |
| status / error | SUCCEEDED 或 FAILED；失败必须保留原因，成功无 error |
| returnedSources | 返回来源数组：url、可空 title、可空 snippet、adoption、adoptionReason、evidenceId |

adoption 为 PENDING / ADOPTED / REJECTED。做出采用决定必须说明理由；ADOPTED 必须关联当前快照内的 evidenceId，可关联保留失败状态的来源线索。记录调用不等于证明服务实质参与，后续需要通过采用理由与证据链审查。检索调用失败和成功但返回空数组分别保留。

## EvidenceSnapshot

| 字段 | 含义 |
|---|---|
| id / investigationId | 快照 ID、所属调查 |
| version / parentSnapshotId | 调查内正整数版本号；第一版为 1 且无父；后续版必须指向同一调查的前一版本 |
| productIdentity | 本快照使用的产品身份 |
| evidence / claims / relations | 证据、主张与主张证据关系 |
| conflicts | 冲突数组，每项 `{id, claimIds, evidenceIds, description, resolution}`；至少一条主张与两条不同证据，resolution 可为 null |
| gaps | 缺口数组，每项 `{id, claimIds, kind, description, searchScope}` |
| retrievalRecords | 本版本实际检索记录 |
| generatedAt / contractVersion | 生成时间与固定版本 `1.0.0` |

Gap.kind 为 NOT_FETCHED / READ_FAILED / NOT_FOUND_IN_SCOPE / IDENTITY_UNCLEAR / INSUFFICIENT_EVIDENCE；NOT_FOUND_IN_SCOPE 必须有明确 searchScope，不能泛称整个互联网没有信息。conflicts、gaps 及检索来源的引用均须指向本快照对象。

各集合 ID 不可重复；禁止自引用父快照。数据库唯一约束 `(investigationId, version)` 防止并发重复版本，复合外键和触发器保证父版本归属与连续性。UPDATE / DELETE 会被不可变触发器拒绝；修正或补查只能新建版本。版本创建仍需处理并发唯一冲突，本阶段不实现自动补查与分配版本重试。

正文作为 JSONB 整体保存，不拆 Evidence/Claim 表。Repository 在写入前、读取后验证 Zod，且核对 JSON 与关系列的 ID、版本、父 ID、时间和契约版本。读取损坏或不支持的契约时抛错，不返回“看似成功”的结果。数据库直接写入也必须走相同校验边界；数据库不会自动执行 Zod。

## Answer 与 Advice

| 对象 / 字段 | 含义 |
|---|---|
| Answer.id / snapshotId | 回答 ID 与所属快照 |
| Answer.body | 客观回答正文 |
| Answer.citations | `{marker, claimIds, evidenceIds, quotes}` 数组；marker 必须出现在正文且不可重复；quotes 为 `{evidenceId, originalExcerpt}` 数组，新写入必须提供并准确覆盖 evidenceIds |
| Answer.generationConfig | 生成配置，见下文 |
| Advice.id / snapshotId | 独立建议 ID 与依据快照 |
| Advice.userConditions | `{useCase, experience, budget, requirements}`；用途必填，其余未知为 null，requirements 为字符串数组 |
| Advice.content / generationConfig | 建议内容和生成配置 |

GenerationConfig 包含 provider、model、promptVersion、可空 temperature（0–2）与 generatedAt。仅允许用于复现的非敏感配置，不保存 API Key、认证头和内部提示正文。

Answer 单独建表，以 snapshotId 外键关联证据快照。Repository 在回答读写时检查引用确实存在于该快照，引用证据已取得原文，并逐字符核对 quotes.originalExcerpt 与该证据的 originalExcerpt；译文、改写或多一个空格都不算匹配。错误导致写入／发布拒绝；GET 时损坏内容被拦截。

quotes 是本次交接新增的 Answer 字段：新写入必填；历史 v1 回答缺少该字段时保留只读兼容，不改写历史 JSON，也不声称它已通过新增的原句比较规则。引用的 ID 与已读状态仍需验证。快照 contractVersion 继续为 1.0.0，因为快照正文结构未改变。三人必须同步当前共享 Schema，不能各自使用旧的 strict DTO。

assertAnswerReferences 只做结构和原句相等检查，不代替“正文是否被证据支持”的语义核查。空引用数组可以表达没有可引用材料的回答，不代表调查业务已经成功。Advice 与 Answer 独立保存；Advice 仍只有模型与契约，没有真实生成实现。

## 队列存储与后续实现边界

Job 保存唯一 investigationId、唯一 idempotencyKey、requestHash、status、availableAt、attemptCount、failureCount/maxAttempts、manualRetryCount、leaseOwner、leaseExpiresAt、heartbeatAt、runDeadlineAt、唯一 executionToken、lastError、confirmationRequest、confirmedIdentity、completionHash、唯一 publishedSnapshotId 和时间戳。第二、三阶段新增字段为内部持久化元数据，不改变快照契约版本。RUNNING 必须有租约与执行截止时间；maxAttempts 限制失败次数，确认等待不消耗失败预算；手动重试至多两次，每次增加一个执行机会，不重置历史计数。

ExecutionAttempt 保存 jobId、attemptNumber、唯一 executionToken、workerId、最新实际 stage、RUNNING/AWAITING_CONFIRMATION/SUCCEEDED/FAILED/LEASE_EXPIRED 状态、开始／心跳／结束时间及错误；`(jobId, attemptNumber)` 唯一。Job.lastError 和 ExecutionAttempt.error 使用共同 ErrorSchema，并在队列写入前验证。

PostgresInvestigationQueue 已实现 ExecutionLease 的原子领取、数据库时间续租、租约到期回收、旧令牌拦截、恢复与幂等发布。任务处理接口、配置与错误分类见 [异步任务队列与租约恢复机制](异步任务队列与租约恢复机制.md)。

第三阶段在 `src/contracts/http.ts` 导出 AcceptedInvestigation、InvestigationDetail、RetryAvailability、SnapshotResponse、IdentityConfirmationBody、RetryBody 和 ApiErrorResponse 的 Schema 与类型。身份确认 Schema 提升到可供浏览器共享的 identity 模块，队列仍重导出原名称。快照的 1.0.0 字段语义保持不变；HTTP 字段见 [HTTP接口与错误码说明](HTTP接口与错误码说明.md)。
