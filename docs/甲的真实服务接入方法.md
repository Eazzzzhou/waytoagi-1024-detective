# 甲的真实服务接入方法

当前真实提供方均未实现。下面列的是待实现入口，不是已接入能力。请先运行 [完整启动步骤](../README.md)，同步 [业务数据契约与字段说明](业务数据契约与字段说明.md)，再接入真实服务。

## 正式入口

`src/server/investigation/handler.ts` 导出的 InvestigationHandler 是唯一正式编排入口。context 包含 investigationId、question、可空 confirmedIdentity、AbortSignal 和 setStage。返回值必须通过 HandlerResultSchema：

```ts
{ kind: "COMPLETE", result: { snapshot, answer } }
// 或
{ kind: "AWAITING_CONFIRMATION", request: { identity, reason } }
```

当前默认 handler 在 IDENTITY 阶段明确抛出 PROVIDER_NOT_CONFIGURED，不会因配置某个环境变量就自动成功。不要通过修改 Worker、添加 Mock 开关或导入测试处理器绕过它。

## 需要实现的服务

| 入口 | 输入 → 输出 | 要求 |
|---|---|---|
| IdentityProvider.resolve | 问题字符串 → ProductIdentity | 区分同名产品、官网、版本、套餐；歧义时 NEEDS_CONFIRMATION，不能猜测 |
| RetrievalProvider.search（元宝适配器） | 查询词、ProductIdentity → RetrievalRecord | 真实调用，记录提供方、查询时间、返回来源与采用理由；元宝须实质参与 |
| SourceProvider.fetch | HTTP(S) URL → Evidence | 取得原文、定位、时间、元数据和内容 SHA-256；失败保留真实状态和原因 |
| ClaimExtractionProvider.extract | Evidence[]、ProductIdentity → Claim[] | 提取原子主张，保留类型和适用范围；不把官方宣称直接当独立实测 |
| VerificationProvider.verify | EvidenceSnapshot → EvidenceSnapshot | 填入关系、核查理由、冲突、缺口和来源独立性；不得改变原文含义 |
| AnswerProvider.generate | EvidenceSnapshot → Answer | 直接回答具体问题、真实引用、保留局限；不默认转成购买建议 |
| ModelProvider.generate | prompt、outputSchema → 经 Schema 解析的结果 | 模型原始响应视为 unknown，先验证再使用，不能只做 TypeScript 类型断言 |

入口路径分别在 `src/server/identity`、`retrieval`、`verification`、`models`。框架没有猜测元宝的 API 地址、认证协议或模型名称；这些必须由甲根据实际可用的官方接入方式实现并验证。

现有 provider 接口未绑定某个 HTTP SDK。甲可以在每次 handler 调用中构造适配器实例，将 context.signal 传入实例／请求；不要在全局变量保存某次调查的身份或取消信号。外部 API 调用不得放入数据库事务。

## 引用与保存

每条 Answer.citations 包含 marker、claimIds、evidenceIds 和新写入必填的 quotes。每项 quote 为 `{evidenceId, originalExcerpt}`，覆盖同一 citation 的 evidenceIds，逐字符复制本快照已保存的原文摘录。不得填译文、改写文本或另一个来源的句子。

公共校验 `assertAnswerReferences` 会检查归属、已读状态与原句相等，不会判断句意是否支持主张。甲还必须核对正文与引用的语义、原句真实性、上下文、版本条件和译文准确性。历史 Answer 缺 quotes 仍可读，不应被解释成新规则已验证的回答。

只返回 snapshot 和 answer，由 Worker 的 queue.complete 在有效租约事务中发布。不要直接调用无令牌 Repository 写入最终快照，不覆盖旧快照。响应丢失时重放相同 ID 与相同结果，不生成一组新 ID 再提交。

## 错误与配置

抛出 `TaskFailure({code,message,retryable})`。429、暂时网络错误等可重试；认证错误、非法结构和未配置提供方不可重试。message 必须具体并脱敏；不得放认证头、密钥、完整内部提示或数据库连接串。

真实密钥仅放服务端 `.env` 或部署环境，接入时在 `.env.example` 追加实际消费的变量、用途和校验规则。禁止 NEXT_PUBLIC_ 密钥。generationConfig 只保存 provider、model、promptVersion、temperature 和 generatedAt。

请传递 AbortSignal；超时、关闭或失去心跳后停止处理。第三方 SDK 不支持取消时，也不能让迟到结果直接写数据库。外部 API 不保证严格一次调用，必要时使用提供方自身的幂等机制。

## 接入后的共同验证

先通过 `npm run verify`，再由三人使用真实产品问题验证：实际元宝参与记录、可定位原句、身份歧义、来源失败、同源转载、冲突与缺口，以及丙对结果的独立复核。当前工程验收只覆盖这些对象的结构和可靠执行，不替代真实效果验收。
