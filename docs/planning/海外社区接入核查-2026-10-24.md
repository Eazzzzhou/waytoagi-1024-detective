# 海外社区接入核查

核查日期：2026-10-24。用途：为“案卷”的海外信息范围与制作顺序提供依据。本轮只查阅文档，未登录账号、购买额度、调用受保护的数据接口，也未验证部署环境可达性。

## 建议结论

海外社区应成为查证的重点信息来源，不能仅作为中文搜索的装饰。建议将 **X、Hacker News、GitHub、相关产品的公开开发者论坛** 纳入第一轮来源评估；论坛按问题选择，不预设一个封闭名单。Reddit 保留在扩展范围，其接入取决于实际获批权限。

元宝承担产品身份、官方事实、中文与公开网页线索发现、争议补查。平台接口负责取得相应社区的原始文本与上下文。海外观点与中文材料一起进入证据核查，不以“来自海外”自动提高可信度。

## 三种能力必须分开

1. **发现链接**：知道某条帖子存在，只有搜索标题或摘要。这一层不能生成原句引语。
2. **取得可核对原文**：有帖子／评论文本、原始链接、时间与必要上下文，可以核验引用；这仍不意味着内容事实正确。
3. **取得互动统计**：平台返回点赞、评论、转发等统计及采集时间，只表示讨论背景，不能代替证据或可信度。

每个来源分别报告这三层的可用情况。缺账号、缺权限、超时、没有命中必须分开，不能统称“未发现相关讨论”。

### X 的关键细节

- 官方搜索页把 Recent Search 标为“Available to all developers”，但同页仍列出批准的开发者账号、Project/App、keys/tokens 等前提。这不能解释为匿名免费接口。[X1]
- 当前官方计费页明确为 pay-per-usage、预购 credits、按返回资源或请求计费；不应沿用旧教程的月费套餐或“免费搜索额度”假设。报价和账号权益以控制台当前状态为准。[X3]
- Post lookup 默认包含原文 `text`，附加请求可取得 `created_at`、`author_id`、`public_metrics`。正文、引用/回复关系、长帖与外链需要按实际返回检查，不能把截断文本当完整陈述。[X2]
- 本轮核查到的是文档能力。一个真实开发者帖的原文获取、引用定位、费用与部署可达性仍须开工验证后才能标“已接入”。

## 适合比赛时间窗的接入顺序

**第一检查点：同时验证元宝主链与 X 权限。** X 是产品重点，不应拖到最后；但验证失败也不能拖住全部产品。明确拿到账号／权限状态、一个真实帖子是否能取原文、访问费用由谁承担。

**第一份可用案卷：元宝＋至少一个可取得原文的海外社区。** 优先 HN/GitHub，具体取决于目标产品在哪里有真实讨论。信息查询可以呈现已核实的事实和有限观点；是否足以给推荐结论，另由推荐规则决定，不能为了展示海外覆盖伪造评价。

**第二步：扩展 X 与相关论坛的证据覆盖。** 保留作者/组织关联、版本、发布时间与原帖 ID，识别同一开发者跨平台发布、转述同一实验、转帖和引用帖，避免“不同平台”被误算成“独立证据”。

**第三步：补互动统计与更多论坛。** 统计不阻塞原文和结论；源清单根据用户的问题、实际讨论位置与接口条件扩展。Reddit 等需要审批的源按项目实际权限推进，不从产品方向里永久排除，也不承诺赛前一定完成。

## 给总策划的交付标准

- 海外材料至少在一份正式查询中进入真实核查与输出；不仅显示平台图标。
- X 的接入状态独立列出：未配置／待授权／已发现链接／已核验原文／读取失败。
- 逐条提供英文原文和可选中文译文，译文不冒充原文；短帖应保留相关回复或引用上下文。
- 官方团队发布是产品事实或官方立场；开发者体验是社区观点。两者都可有价值，但不混算。
- 不能承诺“全网完整覆盖”；展示实际查询来源与缺口。
- 取得原文不等于有权无限保留、转载或再分发；实施者按平台现行规则确定保存与展示方式。
