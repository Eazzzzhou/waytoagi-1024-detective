### A1｜数据获取：元宝与海外原文

**你负责的数据链目标**：给同一查证核心提供实际材料。元宝承担产品事实、调查线索与争议补查；X、HN、GitHub 和相关论坛补充原始社区信息。

**先接收**：产品问题、已确认产品身份或待确认候选、查询范围、调用预算。输出遵循共同 Material 和 SourceRun 定义。

**第一轮动作**：

1. 查既有项目和 `C:/Users/qianchen/Documents/waytoagi-1024-detective/research/` 的线索，核对元宝当前官方文档和账号状态，实际取得一条可记录的元宝响应。
2. 同时核查 X 的账号、权限和费用条件；明确能否取得一个相关公开帖原文。没有权限就记录待授权，不拿摘要伪装原文。
3. 选择一个真实产品，优先取得官方事实材料和至少一个能取原文的海外社区材料。可以从 HN、GitHub、相关公开产品论坛开始。
4. 对每份材料交原始链接、文本、时间、上下文和身份线索；能取原文、只有线索、只能取统计分别说明。
5. 保存查询与读取状态，让 A2 能定位原文，让 C 能显示真实进度和缺源。

**后续按反馈迭代**：增加 X 覆盖、其他论坛、中文体验材料，改进产品/版本识别、原文完整性、访问稳定性与成本。平台按信息价值和可得性决定，保持开放扩展。

**交付**：实际数据适配、真实材料包、查询记录、平台状态表、实测限制。选择新依赖或陌生采集功能前，查已有代码、依赖、官方资料及许可明确的维护中开源方案，记录采用理由。

**本轮完成标准**：A2 可消费材料；B 能定位引用并核对；元宝对结果的实际作用能说明。接口返回 200 或找到一个标题不等于完成。

**边界**：不负责最终推荐规则；不宣称跨平台即独立。访问限制明确返回状态，付费、授权和运行额度按团队已有资源核实。

### A2｜核心算法：主张核查与回答

**你负责的核心目标**：同一套原文处理、来源去重和多模型验证，产出客观搜查回答或按需求建议。

**先接收**：用户问题、回答意图、材料、源状态、可用模型资源。你维护核心结果结构，和 C 对齐最小字段。

**第一轮动作**：

1. 固定最小输出：事实、观点、原句引用、分歧、缺口、来源覆盖；推荐字段可为空。先让“帮我搜一下”完整跑通。
2. 区分出处核对与主张核查。引用可在原文定位，模型输出的 URL 必须来自实际材料。
3. 做产品/版本/条件检查、初步同源识别、事实与官方宣称/用户观点分离。
4. 接入实际可用的模型提取与独立复核。记录分歧，必要时向 A1 请求有上限的补查。运行时模型服务与开发订阅分别确认。
5. 用 B 独立标注的样本比较错误。没有 B 样本时可用明确标注的开发样例搭流程，但正式验收必须有真实样本。

**后续按反馈迭代**：同源识别、否定和条件理解、版本冲突、跨语言对照、反例搜索、停止补查策略和推荐分档。对算法思路做比例适当的一手文献／开源比较，不先训练新模型或堆复杂框架。

**交付**：可调用核心、统一结果结构、算法与规则版本、引用/独立性/冲突处理说明、样本前后对比和失败报告。

**本轮完成标准**：没有用途也能答客观问题；事实、观点有出处；未解决冲突保留；切换成求建议时共用证据。不得用模型意见数量代替独立来源数量。

**边界**：你主做算法；B 主做独立标准和人工复核，C 主做页面。页面不接管分档，人工核查表也不直接代替运行时自动流程。

### B｜独立核查、标注与展示口径

**你的目标**：产出别人可以依据和复测的真实样本，以及用户不会误解的展示口径。此任务可以在核心开发前独立开始。

**先阅读**：当前产品方向、核查规范、来源接入核查。原画像与本版冲突时以本版为准。

**第一轮动作**：

1. 选一个确有公开材料的 AI 产品，人工查找官方事实、一份社区使用材料及可找到的反面或冲突材料。优先包含海外原话；缺失就记录缺失，不凑材料。
2. 逐条记录问题、原始 URL、原文与位置、时间、主张类型、版本条件、人工判断及理由，保留不确定项。
3. 做两种回答样本：一般搜查和带明确用户要求的建议。样本是人工核查参考，不标成系统已跑出的结果。
4. 定义展示口径：事实与宣称怎样区分、观点归谁、译文如何标、同源怎样说明、证据不足和读取失败怎样分别显示。
5. 将标注结果先保存，再查看 A2 输出，对照报告错配、错引、断章取义、译文错误、重复计数、模式误判等具体问题。

**后续按反馈迭代**：逐步扩到能覆盖关键错误的少量样本，例如 8–12 个主张级案例；不是要求一次性建大数据集。围绕新接平台和算法失败补充，淘汰无实际价值的重复样例。

**交付**：可定位真实材料的标注表、展示口径、独立核查记录、具体错误单和复测结果。样本与代码测试分开，公开材料去除不必要个人信息。

**本轮完成标准**：另一位队友能凭记录回到原文，理解人工判断和不确定性；C 能据此显示正确状态；A2 能据此重现一条错误。

**边界**：不实现抓取和交叉验证算法，不需要等待接口；不把模型回答先抄进“标准答案”。对于事实争议，保留依据与分歧，不用个人偏好裁决。

### C｜回答展示、应用接入与交付

**你的目标**：独立完成用户入口和证据阅读体验，再接入你提供的核心输出，形成可访问作品。

**先接收**：共同 Question/Answer/CaseSnapshot 结构，以及 B 的人工真实样本。开发样例与真实运行数据明确分开。

**第一轮动作**：

1. 阅读 `C:/Users/qianchen/Desktop/前端收藏/AGENTS.md`，优先复用现有组件；按需核对外部资源许可。
2. 做产品/问题输入和结果页面。一般搜索直接开始；只有推荐需要关键条件时，在已查内容旁补充询问。
3. 渲染事实、观点原句、单独译文、出处、冲突和来源状态；recommendation 为空时正常显示完整客观案卷。
4. 同一结构支持实际求建议时的用途句、条件和可选八维；不用页面自行重新算档位。
5. 实现加载、缺源、原文不可读、元宝失败、核查未完成、历史快照及移动端状态。
6. 做薄的应用接入层：提交问题、接核心状态、展示结果、保存访问链接。待核心服务可用时替换样例数据提供方，不改查证算法。

**后续按反馈迭代**：用户补充需求、客观/建议转换、窄问题简洁回答、原文定位、雷达入口、平台背景和演示录屏。视觉稿可使用你提供的前端模型建议，由 C 统一合并。

**交付**：可打开页面、交互与状态、核心接入、部署访问结果、演示材料。测试真实浏览器、移动端长文本及来源跳转。

**本轮完成标准**：无用途也能搜；结果读得懂、出处点得开或清楚说明限制；已知事实不会被推荐门槛遮住；后台换数据不需要重做布局。

**边界**：不编写第二套爬取/去重/分档逻辑；不把未接入图标当来源覆盖；不在漂亮样例上结束任务。

## 3. 每轮共同交付什么

下面是带依赖的迭代安排。轮次是可展示的完整行为；四位执行者按上面的职责共同完成。

### R0｜一份共同理解的案卷样本

**阻塞：无，可立即开始。**

交付：一个真实问题和一份人工核查样本、最小共享结构、页面可读样例、元宝和模型/海外来源资源状态。

**完成标准**：四路对同一材料的事实、观点、引语和失败状态解释一致；每路下一步有明确输入。模型 key 或平台权限缺失要成为具体待办，不能藏在“开发中”。

### R1｜用户不提供用途，也能获得客观搜索结果

**阻塞：R0 的最小结构与元宝可用。** B 的其他样本扩充、C 的布局细化可继续独立推进。

交付：用户输入一个真实产品，一条真实元宝驱动的查证链形成可访问回答，能点回原句。

- A1 提供事实材料和可核对文本。
- A2 完成出处与基础主张核查，输出 research 回答。
- B 对照原文独立抽查，记录实际错误。
- C 连接真实核心，提供来源跳转和明确失败态。

**完成标准**：通过规范 V01/V02/V03 等当轮样例；“没说用途”不会阻止一般搜索；只得到搜索摘要的内容不冒充原话。

### R2｜海外观点与冲突成为实际结果的一部分

**阻塞：R1 真数据闭环；目标海外源能合法取得相关原文。** X 或其他平台接入探索可从 R0 并行开始。

交付：至少一份真实案卷包含海外社区原话、中文译文和与其他材料的交叉核对；遇冲突能解释或保留未决。

- A1 按产品实际讨论位置接 X/HN/GitHub/相关论坛，记录逐源状态。
- A2 处理主张、同源和版本冲突，必要时提出有限补查。
- B 标注跨平台共同源头、误译和关键条件。
- C 展示英文原话与译文、正反材料及覆盖范围。

**完成标准**：海外材料对至少一项事实/观点核查产生实际作用；不是只放 logo 或转述“国外都说”；X 是否已经接通单独说明。

### R3｜用户补充要求后，基于同一证据给建议

**阻塞：R1；本轮推荐所需证据已取得。** 不必等所有海外平台全部接通，R2 与推荐局部开发可并行。

交付：用户先查产品，再补充任务/预算；系统复用证据形成有条件建议，必要时明确补查和新增快照。

- A1 执行必要补查，不无理由重复所有采集。
- A2 实现本轮推荐规则、用途证据和条件解释。
- B 对照人工样本验推荐门槛与已知事实展示。
- C 完成补充条件、推荐区和模式切换，客观内容仍保留。

**完成标准**：符合 V04/V05/V12；未请求建议不硬给档位；证据不足明确说明；模型或页面不能跨过采用的规则门槛。

### R4｜真实试用、回归与参赛交付

**阻塞：R1 可用；R2/R3 按实际已完成范围纳入演示。** 招募、材料框架和封面可提前准备。

交付：至少五位目标用户真实使用、关键错误修复、三份正式查询材料、公开作品和成功提交记录。

- B 主持试用与记录，三位成员邀请用户；记录问题、是否点来源、是否理解事实/观点、是否被不必要推荐打断。

**完成标准**：宣传与实际一致；正式查询有答案、理由和可点来源；海外材料及元宝作用真实；推荐不足不被掩饰。保留提交版本，后续试验不直接覆盖它。

## 5. 每轮回报格式

每位负责人只报六项：

1. 本轮完成了哪个可见行为。
2. 产物在哪里，怎样打开或重现。
3. 哪个真实例子通过了，依据是什么。
4. 哪个例子失败，属于哪类错误。
5. 是否改了字段、规则、模型或数据范围，下游受到什么影响。
6. 下一轮最值得做的一项改进。

你据此调整下一轮，不要求队友等一份“大而全最终报告”才交接。错误修复先于来源扩张；新增来源必须证明带来新材料或更好的核查，不能只增加平台数量。
