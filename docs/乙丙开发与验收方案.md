# 乙丙开发与验收方案

更新：2026-10-25。乙丙只维护公共工程、案例与评估、理解／用户验证和演示材料。前端进一步完善已交甲，具体 F1–F6 只在[协作边界](甲与乙丙协作边界.md#甲的前端接手清单)维护，不再给乙丙派相同页面任务。

## 执行顺序与完成条件

| 顺序 | 乙丙任务 | 依赖 | 完成条件 |
|---|---|---|---|
| E1 | 恢复专用测试库连通，按 README 迁移并跑工程回归 | 本地 Docker / PostgreSQL | verify 全部通过；核实托管 CI 结果，不引用旧通过计数 |
| E2 | A/B/C 材料复查、修正参考、组织实际确认和独立复核 | 实际核查者／复核者；材料复查不等甲 | 问题与关闭条件仅更新[案例状态](../cases/D1-状态与验收记录.md)，证据、署名和意见原位记录 |
| E3 | 与甲对齐建议最小契约和调用生命周期，实现建议公共通路 | 契约对齐可先做；真实生成依赖甲 | 请求→幂等异步任务→甲的 Provider→受令牌保护发布→Advice 存取→状态／结果 HTTP 查询完整可用 |
| E4 | 正式调查与建议端到端联调，运行三案真实对照 | 甲的真实能力和前端、E1 / E3 | 正式 API / Worker 产出真实 ID、终态和快照；逐 Q/C/E 对照；失败及条件不足不隐藏 |
| E5 | 两种真实示例与三分钟理解验证 | 真实问题／条件、实际读者；系统验证依赖 E4 | 客观卡＋同一产品建议卡；读者能区分原话／译文／归纳、官方宣称／事实、同源／独立与未知 |
| E6 | 至少五名目标用户实际使用，处理反馈 | 实际参与者、可用系统 | 匿名记录问题、时间、理解及卡点；工程问题乙丙修，页面／生成问题交甲修，必要时复验 |
| E7 | 三份真实查询脚本与截图／录屏素材交核心成员 | E4，相关实际录制 | 覆盖客观、海外冲突、补充真实要求后的建议；每份有答案、一句话说明、可点击来源 |

E1、E2、E3 的设计和工具准备可同步推进；E5 可先用真实材料做明确标注的人工阅读验证，但不算系统试用。没有甲的真实结果、真实参与者或实际复核时保留阻塞，不能以阶段交付代替全部完成。

## 建议通路 E3 的实施范围

已有 AdviceSchema、UserConditionsSchema 和 Advice 表可复用；不存在的部分要实现，不能只等甲的 RecommendationProvider。

- 对齐创建、状态／结果查询、条件不足、错误、重试与幂等语义；建议绑定不可变 snapshotId，允许同快照不同真实条件，不覆盖客观 Answer。
- 设计建议任务类型、输入／结果和唯一范围；当前 Job 与 investigationId 一对一，不能直接塞入多次建议任务。只追加必要迁移，保留原调查行为。
- 增加 Advice Repository 写前／读后校验，处理快照不存在／归属不符、损坏数据和重复发布。
- Worker 调用甲的建议生成，保持租约、心跳、截止、取消、有限重试和原子发布。缺配置如实失败，不返回模拟建议。
- 对外提供甲能直接调用的共享 HTTP Schema；契约及必要迁移就绪后由甲完成 F5 页面。
- 验证并发重复提交、失效令牌、超时／重试、读写校验、失败与条件不足；同时回归原调查任务。

不额外实现自动补查、列表、导出、取消、历史切换或公开部署。

## 真实对照 E4 的实施范围

先用一个范围明确的客观问题跑通正式链路，再扩展三案与建议。Provider 的语义、生成、来源及前端问题交甲；公共契约／API／任务／存储问题由乙丙修复。

D1 CLI 当前要求 investigation 与 snapshot 同时存在。乙丙需补真实失败且无快照的记录路径；在工具补齐前将实际失败写入 case.md，不能写成 NOT_RUN。成功对照使用既有只读评估器和唯一 run-id，不覆盖旧 JSON；自动结构检查不代替人工语义复核。

## D2 展示口径与理解验证

口径只在这里维护；页面实现由甲按协作要求完成。

| 内容 | 验证重点 |
|---|---|
| 事实／宣称／报告／归纳 | 谁说了什么、适用范围和依据可辨；官方说过不代表独立证实，模型归纳不是原句 |
| 原文／译文／引用 | 分开标识，引用回到保存原句、来源、时间和定位 |
| 同源／未知／冲突／缺口 | 不重复计算支持；能指出哪条结论仍不确定、双方条件及缺什么 |
| 客观／建议 | 客观直接回答；建议有真实条件与证据；条件不足不遮住客观内容 |
| 状态 | 真实阶段、失败及历史版本清楚，无假百分比或夹具冒充 |

选择未参与开发的实际读者看三分钟后复述；记录误解，交甲修正页面或生成，复验后才判 D2 通过。三案都是客观问题，不能单独证明建议出口。A-01 仅是客观卡候选，建议问题及条件必须来自真实使用者。
