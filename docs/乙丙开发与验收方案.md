## 建议通路 E3 的实施范围

阶段 3–4 已完成 AdviceRequest／AdviceExecutionAttempt、兼容迁移、存储校验、幂等 HTTP、建议队列及独立 Worker 的工程生命周期；共享定义在 src/contracts/advice-request.ts，执行接入点及状态通路见[协作边界](甲与乙丙协作边界.md#http-边界)。后续修复已接入基于主模型的建议执行适配、语义条件不足分支及原句校验，signal 传到实际模型请求；无凭据仍明确失败。工程替身验证不代表真实 E3 验收完成。

- 提供真实使用者条件和已核验快照，通过正式 API／Worker 验证建议生成及条件不足；预算／经验为 null 不自动判不足，不能编造条件。RecommendationProvider.execute 返回 COMPLETE／INSUFFICIENT_CONDITIONS，generate 保留 Advice 返回接口并增加可选 signal 上下文。
- 已实现 createAdviceHandler → execute → 主模型请求的信号传递，替身 HTTP 验证中止；真实服务仍须核对超时、取消及费用行为。生成与原句／条件核查最多两个模型调用，受 Worker 截止和模型单次时限约束，不增加生成内部自动重试。
- 配置后通过正式 API／独立 Worker 产出真实建议，再回归发布、重试、条件不足及错误路径；当前成功与竞态仅由隔离测试替身触发。
- 当前团队已完成 F5 页面工程接入，待实际凭据验证；未来认证与可信访问策略另行对接。当前仅共享本地工作区，无多用户权限承诺。
- 真实接入后保留失效令牌、超时／重试、原子回滚、重复发布／损坏结果、并发幂等及原调查回归；测试通过不能代替真实建议链路验收。

不额外实现自动补查、列表、导出、取消、历史切换或公开部署。

## 真实对照 E4 的实施范围

先用一个范围明确的客观问题跑通正式链路，再扩展三案与建议。当前团队负责 Provider、页面及公共工程的全部缺陷闭环。

甲侧后端接入仍需真实验证的关闭条件（2026-10-25；已复现的代码缺陷已修复，工程回归结果只见当前状态）：

- 材料已按 36 条分批提取，只标记成功送入的批次，失败尾批可重试，未处理材料显式记缺口；核查优先保留当前主张已有支持／反驳原句。需在真实长材料调查中确认覆盖，而非仅靠合成回归。
- 默认 v4 已支持 REVIEW_MODEL 配置及依赖注入：第二模型先分批独立读全部 READ 原句，再对照主张，主模型按证据裁决并校验后应用；两模型共用总调用／token 预算。未配置明确 NOT_CONFIGURED，同模型或失败不声称复核完成。新增主张不由复核直接补造，仍需后续研究；真实第二模型调用及语义效果待验。
- 无主模型配置已改为 PROVIDER_NOT_CONFIGURED／FAILED，不写零证据成功快照；规划模型服务错误且无原文时也向 Worker 传播失败。真实读取部分材料后遇访问／预算限制仍可保留有范围的结果；无模型 runtime 只验证失败语义，不算真实调查成功。
- 用户已提供原环境报告全文及密钥，当前电脑真实主模型／SearchPro 预检、四条调查与建议成功；第二模型未配置。三案结构 R4 来源分类不完整，逐 Q/C/E 语义仍待核对，不回灌参考、不放宽评估消除失败。两条现有 API 保持不变；环境区别见[缺失项清单](合作者对接与缺失项清单.md)。

D1 CLI 已支持从数据库核实真实 FAILED 调查并记录无快照失败，操作见 [runs 约定](../cases/runs/README.md)。无调查 ID 或数据库记录的实际提交错误仍在 case.md 原位保留，不能写成 NOT_RUN。成功对照使用既有只读评估器和唯一 run-id，不覆盖旧 JSON；自动结构检查不代替人工语义复核。

阶段 5／6 可独立进行的准备已补充离线配置检查及真实建议请求只读留档工具，命令见根 README；按用户要求集中列出的外部缺失项见[合作者对接清单](合作者对接与缺失项清单.md)。留档拒绝覆盖，绑定实际请求、快照及客观回答；没有正式调用时不生成案例成功记录。服务配置、真实条件、独立复核和真人验收补齐后再关闭相关任务。

## D2 展示口径与理解验证

口径只在这里维护；页面和生成由当前团队按协作要求完成。

| 内容 | 验证重点 |
|---|---|
| 事实／宣称／报告／归纳 | 谁说了什么、适用范围和依据可辨；官方说过不代表独立证实，模型归纳不是原句 |
| 原文／译文／引用 | 分开标识，引用回到保存原句、来源、时间和定位 |
| 同源／未知／冲突／缺口 | 不重复计算支持；能指出哪条结论仍不确定、双方条件及缺什么 |
| 客观／建议 | 客观直接回答；建议有真实条件与证据；条件不足不遮住客观内容 |
| 状态 | 真实阶段、失败及历史版本清楚，无假百分比或夹具冒充 |

选择未参与开发的实际读者看三分钟后复述；记录误解，由当前团队修复并实际复验后才判 D2 通过。三案都是客观问题，不能单独证明建议出口。用户已授权选网页／A/B/C 类问题，建议可选网页原问题“我想做自动化工作流，Dify 适合吗？”作验收输入；只使用这句已选用途，预算、经验、设备等不由样稿补造，不把选例等同于实际用户试用。
