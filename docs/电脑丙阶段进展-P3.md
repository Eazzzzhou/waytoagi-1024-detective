## 阅读与证据语义

### 回答与引用

- 原文正文作为 React 文本节点渲染，用 pre-wrap 保留换行，无 dangerouslySetInnerHTML；HTML 标签、脚本和不受信任链接文本不会被执行。
- 只识别 citations 中已保存的 marker；字面匹配，不用文本相似度找证据。相同位置有重叠标记时优先最长的已保存 marker；重复出现的标记均可点击。正文未登记的字符保留纯文本，不自动建立引用关系。
- 单来源 marker 直达当前快照的对应证据；多来源 marker 到本快照该回答的引用映射，再分别跳到全部 evidenceIds。不会把第一条来源当作多来源引用的唯一依据。
- 原文区提供关联主张和返回回答链接；主张区提供关联证据、冲突和缺口链接。目标可获得焦点，并显示定位高亮。
- 每份回答显示自己的 generationConfig.generatedAt，快照生成时间独立放在末段；生成配置收在详情中。历史 v1 引用没有 quotes 时明确说明未单独保存引用原句，保留已有映射，不补造。

### 主张与限制

- 展示 claim.statement、kind、verificationStatus、verificationReason、scope 和对应 relations。
- “尚存限制”只来自 claimIds 精确关联的 gaps 和 conflicts，未引入新 limitation 字段，也不把整份快照的缺口强行套到每条主张。
- 没有证据关系、范围或限制记录时明确说明缺失；不会因为存在 URL、来源或没有缺口记录，就改判为已证明或没有限制。
- OFFICIAL_CLAIM 明确标为官方宣称；来源 OFFICIAL 只说明发布身份，不自动获得独立核查效力。FACT、USER_REPORT、OPINION 按保存类型显示，不重新分类。

### 原文、独立性与缺失

- 显示来源名称、链接、网站、作者、发布时间、获取时间、来源／内容类型、语言、适用版本／套餐、读取状态、原文、译文、定位及上下文。
- READ 才显示原文；FAILED、RESTRICTED、SNIPPET_ONLY、NOT_FETCHED 分开表达。未读来源不显示 blockquote、原文替代句或译文；搜索摘要不冒充原文。
- 独立性直接展示已保存判断与理由；共享上游保留 originGroupId 和 upstreamUrl，并说明多个页面不能自动按多份独立支持计数。没有自行计算独立支持数量。
- 缺失字段用“未知”或明确缺失状态；没有单独的“不适用”契约字段，因此不推测不适用。
- 冲突保留 resolution，有处理说明与尚未解决分别展示；证据不足主张、限定范围内未找到、原文读取失败和未读取来源分别列出，不合并为“没有结果”。

### 数据错误与历史结果

- SnapshotResponseSchema 同时验证快照、引用 ID、可读原文、原句匹配和跨快照关系。失败显示数据／引用校验错误，不生成来源 0、不按相似度替换，也不伪装空结果。
- 继续使用 P2 的真实状态与快照 HTTP 读取：当前执行非 SUCCEEDED 而存在快照时明确标历史；快照请求失败显示错误，已加载的旧快照标明最后读取时间。
- 前端没有执行历史列表 API，未虚构重试次数、历史执行列表或新的历史快照导航。父快照 ID 仅按已有字段显示。
